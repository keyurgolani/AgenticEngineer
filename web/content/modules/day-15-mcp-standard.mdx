### Key Components

| Component     | Role                                          | Examples                                         |
| :------------ | :-------------------------------------------- | :----------------------------------------------- |
| **Host**      | The application that runs the MCP client      | Claude Desktop, ChatGPT, Gemini, Cursor, VS Code |
| **Client**    | Connects to servers, routes requests          | Built into host applications                     |
| **Server**    | Exposes tools, resources, and prompts         | `@modelcontextprotocol/server-filesystem`        |
| **Transport** | Communication layer between client and server | stdio (local), Streamable HTTP (remote)          |

### Transport Options

MCP supports two primary transport mechanisms:

| Transport           | Use Case                     | How It Works                                             |
| :------------------ | :--------------------------- | :------------------------------------------------------- |
| **stdio**           | Local development, CLI tools | Server runs as subprocess, communicates via stdin/stdout |
| **Streamable HTTP** | Remote servers, production   | Single HTTP endpoint for bidirectional messaging         |

<Callout type="info">
  **Streamable HTTP (March 2025):** This transport replaced the older SSE
  (Server-Sent Events) approach. It uses a single HTTP endpoint for all
  communication, simplifying deployment and enabling better scalability. SSE is
  now deprecated—use Streamable HTTP for all new remote servers.
</Callout>

### The Protocol Flow

```
┌─────────────────────────────────────────────────────────┐
│                    Host Application                      │
│  ┌─────────────────────────────────────────────────┐    │
│  │              MCP Client                          │    │
│  │  • Discovers available servers                   │    │
│  │  • Lists tools/resources from each server        │    │
│  │  • Routes tool calls to correct server           │    │
│  │  • Returns results to the LLM                    │    │
│  └─────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────┘
                           │
                    JSON-RPC 2.0
                           │
     ┌─────────────────────┼─────────────────────┐
     ▼                     ▼                     ▼
┌─────────┐          ┌─────────┐          ┌─────────┐
│ Server  │          │ Server  │          │ Server  │
│ (Files) │          │ (DB)    │          │ (Slack) │
│         │          │         │          │         │
│ Tools:  │          │ Tools:  │          │ Tools:  │
│ • read  │          │ • query │          │ • send  │
│ • write │          │ • list  │          │ • read  │
└─────────┘          └─────────┘          └─────────┘
```

## 3.3 The Three Primitives

MCP servers can expose three types of capabilities:

{/* Removed placeholder for primitives visual - Concepts are clear enough with text */}

### 1. Resources (Read-Only Data)

Resources are passive data that the LLM can read. Think of them as GET requests.

```python
# Conceptual example - what a resource looks like
resource = {
    "uri": "file:///home/user/documents/report.pdf",
    "name": "Q4 Report",
    "description": "Quarterly financial report",
    "mimeType": "application/pdf"
}
```

**Use cases:**

- File contents
- Database schemas
- Log files
- Configuration data
- Documentation

### 2. Tools (Executable Functions)

Tools are active functions that perform actions. Think of them as POST requests.

```python
# Conceptual example - what a tool definition looks like
tool = {
    "name": "query_database",
    "description": "Execute a SQL query against the database",
    "inputSchema": {
        "type": "object",
        "properties": {
            "sql": {
                "type": "string",
                "description": "The SQL query to execute"
            }
        },
        "required": ["sql"]
    }
}
```

**Use cases:**

- Database queries
- API calls
- File operations
- Sending messages
- Code execution

### 3. Prompts (Reusable Templates)

Prompts are pre-defined templates for common LLM interactions.

```python
# Conceptual example - what a prompt looks like
prompt = {
    "name": "analyze_code",
    "description": "Analyze code for bugs and improvements",
    "arguments": [
        {
            "name": "code",
            "description": "The code to analyze",
            "required": True
        },
        {
            "name": "language",
            "description": "Programming language",
            "required": False
        }
    ]
}
```

**Use cases:**

- Code review templates
- Data analysis workflows
- Report generation
- Standardized queries

<Callout type="tip">
  **Most Common:** Tools are by far the most commonly used primitive. Resources
  and Prompts are useful for specific scenarios but you'll spend most of your
  time working with Tools.
</Callout>

### Installation


### Basic Server Structure

```python
"""ecommerce_server.py - A simple MCP server"""
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent
import json

# Create the server
server = Server("ecommerce-tools")

# Simulated database
CUSTOMERS = {
    "CUST001": {"name": "Alice Johnson", "email": "alice@example.com"},
    "CUST002": {"name": "Bob Smith", "email": "bob@example.com"},
}

ORDERS = {
    "ORD001": {"customer_id": "CUST001", "items": ["Widget", "Gadget"], "total": 99.99},
    "ORD002": {"customer_id": "CUST002", "items": ["Gizmo"], "total": 49.99},
}


@server.list_tools()
async def list_tools() -> list[Tool]:
    """List all available tools."""
    return [
        Tool(
            name="get_customer",
            description="Get customer information by ID",
            inputSchema={
                "type": "object",
                "properties": {
                    "customer_id": {
                        "type": "string",
                        "description": "The customer ID (e.g., CUST001)"
                    }
                },
                "required": ["customer_id"]
            }
        ),
        Tool(
            name="get_orders",
            description="Get all orders for a customer",
            inputSchema={
                "type": "object",
                "properties": {
                    "customer_id": {
                        "type": "string",
                        "description": "The customer ID"
                    }
                },
                "required": ["customer_id"]
            }
        ),
    ]


@server.call_tool()
async def call_tool(name: str, arguments: dict) -> list[TextContent]:
    """Handle tool calls."""
    if name == "get_customer":
        customer_id = arguments["customer_id"]
        customer = CUSTOMERS.get(customer_id)
        if customer:
            return [TextContent(type="text", text=json.dumps(customer))]
        return [TextContent(type="text", text=f"Customer {customer_id} not found")]

    elif name == "get_orders":
        customer_id = arguments["customer_id"]
        customer_orders = [
            {"order_id": oid, **order}
            for oid, order in ORDERS.items()
            if order["customer_id"] == customer_id
        ]
        return [TextContent(type="text", text=json.dumps(customer_orders))]

    return [TextContent(type="text", text=f"Unknown tool: {name}")]


async def main():
    """Run the server."""
    async with stdio_server() as (read_stream, write_stream):
        await server.run(read_stream, write_stream)


if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

<Callout type="info">
**Transport: stdio vs Streamable HTTP**

This example uses `stdio` (standard input/output) transport, which is ideal for local development and testing. For production deployments, use **Streamable HTTP** transport (introduced in March 2025), which provides bidirectional communication through a single HTTP endpoint. The older SSE transport is now deprecated.

</Callout>

## 3.5 Using FastMCP (Simplified API)

The `mcp` package includes `FastMCP`, a higher-level API that simplifies server creation:

```python
"""ecommerce_fastmcp.py - Using FastMCP for cleaner code"""
from mcp.server.fastmcp import FastMCP

# Create server with FastMCP
mcp = FastMCP("ecommerce-tools")

# Simulated data
CUSTOMERS = {
    "CUST001": {"name": "Alice Johnson", "email": "alice@example.com"},
    "CUST002": {"name": "Bob Smith", "email": "bob@example.com"},
}


@mcp.tool()
def get_customer(customer_id: str) -> dict:
    """
    Get customer information by ID.

    Args:
        customer_id: The customer ID (e.g., CUST001)

    Returns:
        Customer information including name and email
    """
    customer = CUSTOMERS.get(customer_id)
    if customer:
        return customer
    return {"error": f"Customer {customer_id} not found"}


@mcp.tool()
def search_customers(name_query: str) -> list[dict]:
    """
    Search for customers by name.

    Args:
        name_query: Partial name to search for

    Returns:
        List of matching customers
    """
    results = []
    for cid, customer in CUSTOMERS.items():
        if name_query.lower() in customer["name"].lower():
            results.append({"id": cid, **customer})
    return results


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

<Callout type="tip">
**FastMCP Magic:** Notice how the `@mcp.tool()` decorator automatically:
- Extracts the function name as the tool name
- Uses the docstring as the description
- Generates the input schema from type hints
- Handles serialization of return values

This is the recommended approach for most use cases.

</Callout>

## 3.8 Elicitation: Interactive Workflows

One of the most powerful features added in 2025 is **Elicitation**—the ability for MCP servers to request additional information from users mid-execution. This enables truly interactive workflows.

{/* Removed placeholder for elicitation - Mermaid diagram below suffices */}

### How Elicitation Works

Instead of failing when information is missing, a server can pause and ask the user:

<Mermaid
  chart={`
sequenceDiagram
    participant User
    participant Client as MCP Client
    participant Server as MCP Server
    
    User->>Client: "Book a flight to Paris"
    Client->>Server: call_tool("book_flight", {destination: "Paris"})
    Server->>Client: elicitation/create (need travel dates)
    Client->>User: "What dates do you want to travel?"
    User->>Client: "March 15-22"
    Client->>Server: elicitation response
    Server->>Client: Tool result (flight booked!)
    Client->>User: "Flight booked for March 15-22"
`}
/>

### Elicitation Modes

MCP supports two elicitation modes:

| Mode     | Use Case                   | How It Works                                     |
| :------- | :------------------------- | :----------------------------------------------- |
| **Form** | Structured data collection | Server sends JSON Schema, client renders form    |
| **URL**  | OAuth flows, external auth | Server sends URL, user completes flow in browser |

### Form Mode Example

```python
# Server-side: requesting user information
@mcp.tool()
async def book_appointment(service: str) -> dict:
    """Book an appointment for a service."""
    # Request additional info via elicitation
    user_info = await mcp.elicit(
        message="Please provide your contact details",
        schema={
            "type": "object",
            "properties": {
                "name": {"type": "string", "description": "Your full name"},
                "email": {"type": "string", "format": "email"},
                "preferred_date": {"type": "string", "format": "date"},
                "notes": {"type": "string", "description": "Any special requests"}
            },
            "required": ["name", "email", "preferred_date"]
        }
    )

    # Now we have the user's info
    return {
        "status": "booked",
        "service": service,
        "customer": user_info["name"],
        "date": user_info["preferred_date"]
    }
```

### URL Mode for OAuth

URL elicitation is essential for secure authentication flows:

```python
@mcp.tool()
async def connect_github() -> dict:
    """Connect your GitHub account."""
    # Redirect user to OAuth flow
    auth_result = await mcp.elicit(
        mode="url",
        message="Please authorize access to your GitHub account",
        url="https://github.com/login/oauth/authorize?client_id=..."
    )

    # User completed OAuth, we have the token
    return {"status": "connected", "username": auth_result["username"]}
```

<Callout type="tip">
**When to Use Elicitation:**
- Collecting missing required information
- OAuth/authentication flows
- User confirmation before destructive actions
- Multi-step wizards within a single tool call

Elicitation keeps the user in control while enabling richer interactions.

</Callout>

## 3.9 OAuth 2.1 Authorization

The June 2025 specification update introduced comprehensive **OAuth 2.1 authorization** for MCP, making it enterprise-ready. This is critical for production deployments where servers access sensitive resources.

{/* Removed placeholder for Auth - Sequence diagram covers this well */}

### Key Security Features

| Feature                 | Purpose                                          |
| :---------------------- | :----------------------------------------------- |
| **Mandatory PKCE**      | Prevents authorization code interception attacks |
| **OAuth 2.1 Base**      | Modern security defaults, no implicit flow       |
| **Resource Indicators** | Specify which resources a token can access       |
| **Token Binding**       | Tokens tied to specific client instances         |

### Authorization Flow

```
┌─────────────────────────────────────────────────────────┐
│                    MCP Client                            │
│  1. Discovers server's authorization endpoint            │
│  2. Generates PKCE code_verifier and code_challenge      │
│  3. Redirects user to authorization server               │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│              Authorization Server (IdP)                  │
│  4. User authenticates and grants permissions            │
│  5. Returns authorization code to client                 │
└─────────────────────────────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────┐
│                    MCP Client                            │
│  6. Exchanges code + code_verifier for access token      │
│  7. Uses token to authenticate with MCP server           │
└─────────────────────────────────────────────────────────┘
```

### Server-Side Authorization

```python
from mcp.server.fastmcp import FastMCP
from mcp.server.auth import OAuth2Config

mcp = FastMCP(
    "secure-server",
    auth=OAuth2Config(
        issuer="https://auth.example.com",
        audience="https://api.example.com",
        scopes=["read:data", "write:data"]
    )
)

@mcp.tool()
async def get_sensitive_data(query: str) -> dict:
    """Access sensitive data (requires authentication)."""
    # Token is automatically validated by the framework
    # Access user info from the request context
    user = mcp.get_current_user()

    # Check scopes
    if "read:data" not in user.scopes:
        return {"error": "Insufficient permissions"}

    return {"data": f"Sensitive results for {query}"}
```

<Callout type="warning">
  **Security Best Practices:** - Always use HTTPS for remote MCP servers -
  Implement proper scope validation - Use short-lived access tokens with refresh
  tokens - Log all tool invocations for audit trails - Consider rate limiting to
  prevent abuse
</Callout>

## 3.10 Recent Protocol Updates (November 2025)

The MCP specification continues to evolve. The November 2025 release introduced several important features for production deployments:

### Asynchronous Operations (Tasks)

Long-running operations like report generation or data analysis can now run asynchronously:

```python
# Conceptual example - async task pattern
@mcp.tool()
async def generate_report(data_source: str) -> dict:
    """
    Generate a comprehensive report (may take several minutes).
    Returns a task ID for polling.
    """
    task_id = await start_background_task(data_source)
    return {"task_id": task_id, "status": "processing"}

@mcp.tool()
async def get_task_status(task_id: str) -> dict:
    """Check the status of a long-running task."""
    return await check_task(task_id)
```

### Stateless Mode

Servers can now operate in stateless mode, enabling horizontal scaling and serverless deployments:

```python
# Stateless server configuration
mcp = FastMCP("stateless-server", stateless=True)
```

### Server Identity

Servers can now declare their identity, enabling better security and audit trails:

```python
server = Server(
    "my-server",
    identity={
        "name": "Production Database Server",
        "version": "1.2.0",
        "vendor": "MyCompany"
    }
)
```

### Client ID Metadata Documents

Enterprise deployments can now use metadata documents to describe client capabilities and requirements, improving interoperability in complex environments.

<Callout type="info">
  **Specification Versions:** MCP uses dated specification versions (e.g.,
  `2025-11-25`). When building production systems, specify the version you're
  targeting to ensure compatibility. Key versions: March 2025 (Streamable HTTP),
  June 2025 (OAuth 2.1, Elicitation), November 2025 (Tasks, Stateless mode).
</Callout>

MCP isn't always the right choice. Here's a decision framework:

## 3.14 The Taskmaster Pattern: Task-Based Agent Orchestration

Complex agent workflows often involve multiple steps that need coordination, error recovery, and the ability to undo mistakes. The **Taskmaster pattern** provides a structured approach to managing these workflows through task-based orchestration with full undo/redo support.

<ConceptIntro
  title="Taskmaster Pattern"
  analogy="Think of a project manager who breaks down a large project into tasks, tracks their status, and can roll back changes when something goes wrong. The Taskmaster pattern gives your agent this same capability—decomposing complex goals into manageable tasks with full history tracking."
  technicalDef="The Taskmaster pattern is an architectural approach for agent orchestration that manages work as discrete tasks with lifecycle states, dependency tracking, and reversible action history. ### Task Data Model

```typescript
interface Task {
  id: string; // Unique identifier
  description: string; // Human-readable description
  status: "pending" | "in_progress" | "completed" | "failed";
  dependencies: string[]; // IDs of tasks that must complete first
  result?: any; // Output when completed
  error?: string; // Error message if failed
  createdAt: Date;
  updatedAt: Date;
  metadata?: Record<string, any>; // Custom data (priority, tags, etc.)
}

interface TaskAction {
  id: string;
  taskId: string;
  type: string; // Action type (e.g., 'file_write', 'api_call')
  params: Record<string, any>; // Action parameters
  result?: any; // Action result
  reversible: boolean; // Can this action be undone?
  reverseAction?: TaskAction; // How to undo this action
  timestamp: Date;
}
```

### Complete TaskManager Implementation

```python
"""taskmaster.py - Task-based agent orchestration with undo/redo"""
from dataclasses import dataclass, field
from datetime import datetime
from enum import Enum
from typing import Any, Callable, Optional
import uuid


class TaskStatus(Enum):
    PENDING = "pending"
    IN_PROGRESS = "in_progress"
    COMPLETED = "completed"
    FAILED = "failed"


@dataclass
class Task:
    """A single task in the workflow."""
    id: str
    description: str
    status: TaskStatus = TaskStatus.PENDING
    dependencies: list[str] = field(default_factory=list)
    result: Any = None
    error: Optional[str] = None
    created_at: datetime = field(default_factory=datetime.now)
    updated_at: datetime = field(default_factory=datetime.now)
    metadata: dict = field(default_factory=dict)


@dataclass
class TaskAction:
    """A reversible action taken during task execution."""
    id: str
    task_id: str
    action_type: str
    params: dict
    result: Any = None
    reversible: bool = True
    reverse_params: Optional[dict] = None
    timestamp: datetime = field(default_factory=datetime.now)


class ActionHistory:
    """Manages action history for undo/redo functionality."""

    def __init__(self, max_history: int = 100):
        self.history: list[TaskAction] = []
        self.redo_stack: list[TaskAction] = []
        self.max_history = max_history

    def record(self, action: TaskAction) -> None:
        """Record an action to history."""
        self.history.append(action)
        self.redo_stack.clear()  # Clear redo stack on new action

        # Trim history if needed
        if len(self.history) > self.max_history:
            self.history = self.history[-self.max_history:]

    def can_undo(self) -> bool:
        """Check if undo is available."""
        return len(self.history) > 0 and self.history[-1].reversible

    def can_redo(self) -> bool:
        """Check if redo is available."""
        return len(self.redo_stack) > 0

    def pop_for_undo(self) -> Optional[TaskAction]:
        """Get the last action for undoing."""
        if not self.can_undo():
            return None
        action = self.history.pop()
        self.redo_stack.append(action)
        return action

    def pop_for_redo(self) -> Optional[TaskAction]:
        """Get the last undone action for redoing."""
        if not self.can_redo():
            return None
        action = self.redo_stack.pop()
        self.history.append(action)
        return action

    def get_history(self, limit: int = 10) -> list[TaskAction]:
        """Get recent action history."""
        return self.history[-limit:]


class TaskManager:
    """Manages tasks with full lifecycle and undo/redo support."""

    def __init__(self):
        self.tasks: dict[str, Task] = {}
        self.action_history = ActionHistory()
        self.action_handlers: dict[str, Callable] = {}
        self.reverse_handlers: dict[str, Callable] = {}

    def register_action(
        self,
        action_type: str,
        handler: Callable,
        reverse_handler: Optional[Callable] = None
    ) -> None:
        """Register an action handler with optional reverse handler."""
        self.action_handlers[action_type] = handler
        if reverse_handler:
            self.reverse_handlers[action_type] = reverse_handler

    # --- Task CRUD Operations ---

    def create_task(
        self,
        description: str,
        dependencies: list[str] = None,
        metadata: dict = None
    ) -> Task:
        """Create a new task."""
        task = Task(
            id=str(uuid.uuid4())[:8],
            description=description,
            dependencies=dependencies or [],
            metadata=metadata or {}
        )
        self.tasks[task.id] = task
        return task

    def get_task(self, task_id: str) -> Optional[Task]:
        """Get a task by ID."""
        return self.tasks.get(task_id)

    def list_tasks(
        self,
        status: Optional[TaskStatus] = None
    ) -> list[Task]:
        """List tasks, optionally filtered by status."""
        tasks = list(self.tasks.values())
        if status:
            tasks = [t for t in tasks if t.status == status]
        return sorted(tasks, key=lambda t: t.created_at)

    def update_task(
        self,
        task_id: str,
        **updates
    ) -> Optional[Task]:
        """Update task fields."""
        task = self.tasks.get(task_id)
        if not task:
            return None

        for key, value in updates.items():
            if hasattr(task, key):
                setattr(task, key, value)
        task.updated_at = datetime.now()
        return task

    def delete_task(self, task_id: str) -> bool:
        """Delete a task."""
        if task_id in self.tasks:
            del self.tasks[task_id]
            return True
        return False

    # --- Task Execution ---

    def can_execute(self, task_id: str) -> bool:
        """Check if a task can be executed (dependencies met)."""
        task = self.tasks.get(task_id)
        if not task or task.status != TaskStatus.PENDING:
            return False

        for dep_id in task.dependencies:
            dep = self.tasks.get(dep_id)
            if not dep or dep.status != TaskStatus.COMPLETED:
                return False
        return True

    def execute_action(
        self,
        task_id: str,
        action_type: str,
        params: dict,
        reversible: bool = True
    ) -> TaskAction:
        """Execute an action within a task context."""
        task = self.tasks.get(task_id)
        if not task:
            raise ValueError(f"Task {task_id} not found")

        # Update task status
        task.status = TaskStatus.IN_PROGRESS
        task.updated_at = datetime.now()

        # Get handler
        handler = self.action_handlers.get(action_type)
        if not handler:
            raise ValueError(f"No handler for action type: {action_type}")

        # Execute action
        try:
            result = handler(**params)

            # Create action record
            action = TaskAction(
                id=str(uuid.uuid4())[:8],
                task_id=task_id,
                action_type=action_type,
                params=params,
                result=result,
                reversible=reversible and action_type in self.reverse_handlers
            )

            # Record to history
            self.action_history.record(action)

            return action

        except Exception as e:
            task.status = TaskStatus.FAILED
            task.error = str(e)
            task.updated_at = datetime.now()
            raise

    def complete_task(
        self,
        task_id: str,
        result: Any = None
    ) -> Optional[Task]:
        """Mark a task as completed."""
        task = self.tasks.get(task_id)
        if task:
            task.status = TaskStatus.COMPLETED
            task.result = result
            task.updated_at = datetime.now()
        return task

    def fail_task(
        self,
        task_id: str,
        error: str
    ) -> Optional[Task]:
        """Mark a task as failed."""
        task = self.tasks.get(task_id)
        if task:
            task.status = TaskStatus.FAILED
            task.error = error
            task.updated_at = datetime.now()
        return task

    # --- Undo/Redo Operations ---

    def undo(self) -> Optional[dict]:
        """Undo the last action."""
        action = self.action_history.pop_for_undo()
        if not action:
            return {"success": False, "reason": "Nothing to undo"}

        reverse_handler = self.reverse_handlers.get(action.action_type)
        if not reverse_handler:
            return {"success": False, "reason": "Action not reversible"}

        try:
            # Execute reverse action
            reverse_handler(**action.params, original_result=action.result)
            return {
                "success": True,
                "undone_action": action.action_type,
                "task_id": action.task_id
            }
        except Exception as e:
            return {"success": False, "reason": str(e)}

    def redo(self) -> Optional[dict]:
        """Redo the last undone action."""
        action = self.action_history.pop_for_redo()
        if not action:
            return {"success": False, "reason": "Nothing to redo"}

        handler = self.action_handlers.get(action.action_type)
        if not handler:
            return {"success": False, "reason": "Handler not found"}

        try:
            result = handler(**action.params)
            action.result = result
            return {
                "success": True,
                "redone_action": action.action_type,
                "task_id": action.task_id
            }
        except Exception as e:
            return {"success": False, "reason": str(e)}

    def get_undo_redo_status(self) -> dict:
        """Get current undo/redo availability."""
        return {
            "can_undo": self.action_history.can_undo(),
            "can_redo": self.action_history.can_redo(),
            "history_length": len(self.action_history.history),
            "redo_stack_length": len(self.action_history.redo_stack)
        }
```

### Reversible vs Irreversible Actions

Not all actions can be undone. Design your system to handle both:

| Action Type     | Reversible? | Reverse Strategy                       |
| :-------------- | :---------- | :------------------------------------- |
| File write      | ✅ Yes      | Restore from backup/previous content   |
| Database INSERT | ✅ Yes      | DELETE the inserted row                |
| Database UPDATE | ✅ Yes      | UPDATE with previous values            |
| Email sent      | ❌ No       | Cannot unsend                          |
| API webhook     | ❌ No       | External side effects                  |
| File delete     | ⚠️ Partial  | Restore from trash/backup if available |

```python
# Example: Registering reversible file operations
def write_file(path: str, content: str) -> dict:
    """Write content to a file (reversible)."""
    import os

    # Save original content for undo
    original = None
    if os.path.exists(path):
        with open(path, 'r') as f:
            original = f.read()

    with open(path, 'w') as f:
        f.write(content)

    return {"path": path, "original_content": original}


def reverse_write_file(path: str, content: str, original_result: dict) -> None:
    """Reverse a file write operation."""
    original = original_result.get("original_content")
    if original is not None:
        with open(path, 'w') as f:
            f.write(original)
    else:
        import os
        os.remove(path)  # File didn't exist before


# Register with TaskManager
task_manager = TaskManager()
task_manager.register_action("file_write", write_file, reverse_write_file)
```

### MCP Server Implementation

```python
"""taskmaster_mcp.py - Taskmaster as an MCP server"""
from mcp.server.fastmcp import FastMCP
from taskmaster import TaskManager, TaskStatus

# Initialize
mcp = FastMCP("taskmaster")
task_manager = TaskManager()


# --- Task Management Tools ---

@mcp.tool()
def create_task(
    description: str,
    dependencies: list[str] = None,
    priority: str = "medium"
) -> dict:
    """
    Create a new task in the workflow.

    Args:
        description: What the task should accomplish
        dependencies: List of task IDs that must complete first
        priority: Task priority (low, medium, high)

    Returns:
        The created task with its ID
    """
    task = task_manager.create_task(
        description=description,
        dependencies=dependencies or [],
        metadata={"priority": priority}
    )
    return {
        "id": task.id,
        "description": task.description,
        "status": task.status.value,
        "dependencies": task.dependencies,
        "priority": priority
    }


@mcp.tool()
def list_tasks(status: str = None) -> list[dict]:
    """
    List all tasks, optionally filtered by status.

    Args:
        status: Filter by status (pending, in_progress, completed, failed)

    Returns:
        List of tasks matching the filter
    """
    filter_status = TaskStatus(status) if status else None
    tasks = task_manager.list_tasks(status=filter_status)
    return [
        {
            "id": t.id,
            "description": t.description,
            "status": t.status.value,
            "dependencies": t.dependencies,
            "result": t.result,
            "error": t.error
        }
        for t in tasks
    ]


@mcp.tool()
def get_task(task_id: str) -> dict:
    """
    Get details of a specific task.

    Args:
        task_id: The task ID to retrieve

    Returns:
        Task details or error if not found
    """
    task = task_manager.get_task(task_id)
    if not task:
        return {"error": f"Task {task_id} not found"}
    return {
        "id": task.id,
        "description": task.description,
        "status": task.status.value,
        "dependencies": task.dependencies,
        "result": task.result,
        "error": task.error,
        "created_at": task.created_at.isoformat(),
        "updated_at": task.updated_at.isoformat()
    }


@mcp.tool()
def complete_task(task_id: str, result: str = None) -> dict:
    """
    Mark a task as completed.

    Args:
        task_id: The task to complete
        result: Optional result or output from the task

    Returns:
        Updated task status
    """
    task = task_manager.complete_task(task_id, result)
    if not task:
        return {"error": f"Task {task_id} not found"}
    return {"id": task.id, "status": "completed", "result": result}


@mcp.tool()
def fail_task(task_id: str, error: str) -> dict:
    """
    Mark a task as failed.

    Args:
        task_id: The task that failed
        error: Description of what went wrong

    Returns:
        Updated task status
    """
    task = task_manager.fail_task(task_id, error)
    if not task:
        return {"error": f"Task {task_id} not found"}
    return {"id": task.id, "status": "failed", "error": error}


# --- Undo/Redo Tools ---

@mcp.tool()
def undo_last_action() -> dict:
    """
    Undo the last reversible action.

    Returns:
        Result of the undo operation
    """
    return task_manager.undo()


@mcp.tool()
def redo_last_action() -> dict:
    """
    Redo the last undone action.

    Returns:
        Result of the redo operation
    """
    return task_manager.redo()


@mcp.tool()
def get_action_history(limit: int = 10) -> dict:
    """
    Get recent action history and undo/redo status.

    Args:
        limit: Maximum number of history items to return

    Returns:
        Action history and undo/redo availability
    """
    status = task_manager.get_undo_redo_status()
    history = task_manager.action_history.get_history(limit)
    return {
        **status,
        "recent_actions": [
            {
                "id": a.id,
                "type": a.action_type,
                "task_id": a.task_id,
                "reversible": a.reversible,
                "timestamp": a.timestamp.isoformat()
            }
            for a in history
        ]
    }


# --- Workflow Tools ---

@mcp.tool()
def get_next_tasks() -> list[dict]:
    """
    Get tasks that are ready to execute (dependencies met).

    Returns:
        List of executable tasks
    """
    pending = task_manager.list_tasks(status=TaskStatus.PENDING)
    ready = [t for t in pending if task_manager.can_execute(t.id)]
    return [
        {
            "id": t.id,
            "description": t.description,
            "priority": t.metadata.get("priority", "medium")
        }
        for t in ready
    ]


@mcp.tool()
def get_workflow_status() -> dict:
    """
    Get overall workflow status summary.

    Returns:
        Summary of task counts by status
    """
    all_tasks = task_manager.list_tasks()
    return {
        "total": len(all_tasks),
        "pending": len([t for t in all_tasks if t.status == TaskStatus.PENDING]),
        "in_progress": len([t for t in all_tasks if t.status == TaskStatus.IN_PROGRESS]),
        "completed": len([t for t in all_tasks if t.status == TaskStatus.COMPLETED]),
        "failed": len([t for t in all_tasks if t.status == TaskStatus.FAILED]),
        "ready_to_execute": len([t for t in all_tasks if task_manager.can_execute(t.id)])
    }


if __name__ == "__main__":
    mcp.run(transport="stdio")
```

### Using Taskmaster from an Agent

```python
# Example: Agent using Taskmaster MCP tools
async def plan_and_execute(goal: str):
    """Break down a goal into tasks and execute them."""

    # Step 1: Create tasks for the goal
    tasks = await mcp_client.call_tool("create_task", {
        "description": f"Research: {goal}",
        "priority": "high"
    })

    await mcp_client.call_tool("create_task", {
        "description": f"Draft solution for: {goal}",
        "dependencies": [tasks["id"]],
        "priority": "high"
    })

    await mcp_client.call_tool("create_task", {
        "description": f"Review and finalize: {goal}",
        "dependencies": [tasks["id"]],
        "priority": "medium"
    })

    # Step 2: Execute ready tasks
    while True:
        ready = await mcp_client.call_tool("get_next_tasks", {})
        if not ready:
            break

        for task in ready:
            # Execute task logic here
            result = await execute_task_logic(task)

            if result["success"]:
                await mcp_client.call_tool("complete_task", {
                    "task_id": task["id"],
                    "result": result["output"]
                })
            else:
                await mcp_client.call_tool("fail_task", {
                    "task_id": task["id"],
                    "error": result["error"]
                })

    # Step 3: Get final status
    return await mcp_client.call_tool("get_workflow_status", {})
```

## 3.16 Voice-First Task Management

The Taskmaster pattern works exceptionally well with voice interfaces, enabling natural language task management.

### Voice Command Patterns

| Voice Command                    | Taskmaster Action                          |
| :------------------------------- | :----------------------------------------- |
| "Create a task to review the PR" | `create_task(description="Review the PR")` |
| "What tasks are pending?"        | `list_tasks(status="pending")`             |
| "Mark the research task as done" | `complete_task(task_id="...")`             |
| "Undo that last change"          | `undo_last_action()`                       |
| "What's the project status?"     | `get_workflow_status()`                    |
| "What should I work on next?"    | `get_next_tasks()`                         |

### Voice Integration Example

```python
"""voice_taskmaster.py - Voice-first task management"""
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("voice-taskmaster")


@mcp.tool()
def process_voice_command(transcript: str) -> dict:
    """
    Process a voice command for task management.

    Args:
        transcript: The transcribed voice command

    Returns:
        Action taken and result
    """
    transcript_lower = transcript.lower()

    # Task creation patterns
    if any(phrase in transcript_lower for phrase in ["create a task", "add a task", "new task"]):
        # Extract task description
        description = extract_task_description(transcript)
        return create_task(description)

    # Status queries
    if any(phrase in transcript_lower for phrase in ["what's pending", "pending tasks", "what tasks"]):
        return list_tasks(status="pending")

    # Completion patterns
    if any(phrase in transcript_lower for phrase in ["mark as done", "complete", "finished"]):
        task_ref = extract_task_reference(transcript)
        return complete_task(task_ref)

    # Undo patterns
    if any(phrase in transcript_lower for phrase in ["undo", "revert", "take back"]):
        return undo_last_action()

    # Status overview
    if any(phrase in transcript_lower for phrase in ["project status", "how are we doing", "overview"]):
        return get_workflow_status()

    # Next task
    if any(phrase in transcript_lower for phrase in ["what's next", "next task", "what should i"]):
        return get_next_tasks()

    return {"error": "Command not recognized", "transcript": transcript}


def extract_task_description(transcript: str) -> str:
    """Extract task description from voice transcript."""
    # Simple extraction - in production, use NLP
    markers = ["to ", "for ", "about "]
    for marker in markers:
        if marker in transcript.lower():
            idx = transcript.lower().index(marker)
            return transcript[idx + len(marker):].strip()
    return transcript


def extract_task_reference(transcript: str) -> str:
    """Extract task reference from voice transcript."""
    # In production, use fuzzy matching against task descriptions
    return transcript
```
