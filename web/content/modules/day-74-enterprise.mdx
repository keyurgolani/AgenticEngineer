## 74.2 Case Study: Retail - Proactive Shopping Assistant

{/* IMAGE_PLACEHOLDER: Create a flowchart illustration showing a customer's journey through an e-commerce site with the proactive agent intervening at key moments. Show: 1) Customer viewing product (agent observing), 2) Customer hovering over cart button (hesitation detected), 3) Agent offering help with a friendly chat bubble, 4) Either conversion or escalation to human. Use e-commerce UI elements and friendly, modern design. Include metrics/stats overlays showing the 70% abandonment rate problem. */}

### The Problem

High cart abandonment rates (industry average: 70%). Traditional chatbots only respond when asked.

**Real-World Impact:** For a retailer with $10M in monthly traffic, a 70% abandonment rate means $7M in potential lost revenue. Even a 5% improvement in conversion translates to $350K monthly.

### The Agent Strategy

Not just a chatbot—a proactive agent that:

- Tracks user behavior (clicks, dwell time, scroll patterns)
- Identifies hesitation signals
- Proactively offers contextual help
- Escalates to humans when confidence is low

**The Key Insight:** Most customers don't ask for help even when they need it. A proactive agent detects confusion before the customer abandons their cart.

### Architecture

```python
from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Literal

class ShopperState(TypedDict):
    user_id: str
    session_events: list[dict]
    hesitation_score: float
    intervention_type: Literal["none", "nudge", "chat", "human"]
    outcome: str

class ProactiveShopperAgent:
    """Proactive shopping assistant that intervenes based on behavior."""

    def analyze_behavior(self, state: ShopperState) -> dict:
        """Analyze user behavior for hesitation signals."""
        events = state["session_events"]

        # Hesitation signals
        signals = {
            "repeated_product_views": self._count_repeated_views(events),
            "cart_hover_without_add": self._detect_cart_hover(events),
            "price_comparison_pattern": self._detect_comparison(events),
            "long_dwell_time": self._check_dwell_time(events),
        }

        score = sum(signals.values()) / len(signals)

        return {"hesitation_score": score}

    def decide_intervention(self, state: ShopperState) -> dict:
        """Decide what type of intervention to make."""
        score = state["hesitation_score"]

        if score < 0.3:
            return {"intervention_type": "none"}
        elif score < 0.5:
            return {"intervention_type": "nudge"}  # Subtle UI hint
        elif score < 0.7:
            return {"intervention_type": "chat"}   # Proactive chat
        else:
            return {"intervention_type": "human"}  # Human handoff

    def execute_intervention(self, state: ShopperState) -> dict:
        """Execute the chosen intervention."""
        intervention = state["intervention_type"]

        if intervention == "nudge":
            # Show "X people bought this today" or similar
            return {"outcome": "nudge_displayed"}
        elif intervention == "chat":
            # Open chat with contextual message
            message = self._generate_contextual_message(state)
            return {"outcome": f"chat_initiated: {message}"}
        elif intervention == "human":
            # Route to human agent with context
            return {"outcome": "human_handoff"}

        return {"outcome": "no_intervention"}
```

## 74.3 Case Study: Logistics - Intelligent Routing

{/* IMAGE_PLACEHOLDER: Create an animated-style illustration of a city map with delivery trucks, showing multiple routes being dynamically adjusted. Show before/after comparison with original routes in gray and optimized routes in green. Add small agent icons (planner, monitor, optimizer, coordinator) working together around the map. */}

### The Problem

Complex delivery networks with dynamic conditions (traffic, weather, vehicle availability).

**The Challenge:** A logistics company with 500 daily deliveries faces:
- 50+ route changes per day due to traffic
- Weather-related delays costing $10K+ weekly
- Manual route adjustments taking 15-20 minutes each
- Driver frustration from constant route changes

### The Agent Strategy

Multi-agent system for route optimization:

- **Planner Agent**: Creates initial routes (like a chess player planning opening moves)
- **Monitor Agent**: Watches real-time conditions (like a weather forecaster + traffic reporter)
- **Optimizer Agent**: Adjusts routes dynamically (like a GPS that actually thinks ahead)
- **Coordinator Agent**: Manages driver communication (like an air traffic controller for trucks)

### Architecture

### Key Patterns

```python
class LogisticsOrchestrator:
    """Enterprise logistics orchestration with reliability patterns."""

    def __init__(self):
        self.planner = PlannerAgent()
        self.monitor = MonitorAgent()
        self.optimizer = OptimizerAgent()

        # Enterprise patterns
        self.circuit_breaker = CircuitBreaker(
            failure_threshold=5,
            recovery_timeout=60
        )
        self.rate_limiter = RateLimiter(
            requests_per_minute=100
        )

    async def optimize_route(self, route_id: str) -> dict:
        """Optimize a route with enterprise reliability patterns."""

        # Circuit breaker prevents cascade failures
        if self.circuit_breaker.is_open():
            return self._fallback_route(route_id)

        try:
            # Rate limiting prevents API exhaustion
            await self.rate_limiter.acquire()

            # Get current conditions
            conditions = await self.monitor.get_conditions(route_id)

            # Optimize if needed
            if conditions["disruption_score"] > 0.5:
                new_route = await self.optimizer.optimize(
                    route_id,
                    conditions
                )

                # Audit log
                await self._log_optimization(
                    route_id,
                    conditions,
                    new_route
                )

                return new_route

            return {"status": "no_change_needed"}

        except Exception as e:
            self.circuit_breaker.record_failure()
            return self._fallback_route(route_id)
```

## 74.4 Case Study: Financial Services - Compliance Agent

{/* IMAGE_PLACEHOLDER: Create a professional illustration showing a document review workflow. Show documents flowing through different stages: 1) Document intake with PII redaction, 2) AI analysis with magnifying glass highlighting issues, 3) Risk scoring with color-coded risk levels (green/yellow/red), 4) Human reviewer at desk for high-risk items. Include security and compliance icons (locks, shields, checkmarks). Use financial services color palette (navy, gold, white). */}

### The Problem

Manual compliance review is slow, expensive, and inconsistent.

**The Cost of Manual Review:**
- Average review time: 2-4 hours per document
- Compliance team cost: $150-300/hour
- Inconsistency rate: 15-20% (different reviewers, different conclusions)
- Backlog: 2-3 weeks for standard reviews

### The Agent Strategy

AI-assisted compliance review with human-in-the-loop:

- **Analyzer Agent**: Reviews documents for compliance issues (like a junior analyst doing the first pass)
- **Risk Scorer**: Assigns risk levels to findings (like a risk manager prioritizing issues)
- **Recommender**: Suggests remediation actions (like a senior consultant providing guidance)
- **Human Review**: Final approval for high-risk items (like a compliance officer signing off)

**Critical Design Decision:** High-risk items (>0.7 risk score) ALWAYS require human approval. This is non-negotiable in regulated industries.

### Critical Enterprise Patterns

```python
class ComplianceAgent:
    """Compliance agent with enterprise governance."""

    def __init__(self):
        self.llm = ChatOpenAI(model="gpt-4o")

        # RBAC: Different users see different data
        self.rbac = RBACManager()

        # Audit: Every action logged
        self.audit_log = AuditLogger()

        # PII: Sensitive data handling
        self.pii_handler = PIIHandler()

    async def review_document(
        self,
        document: str,
        user: User
    ) -> ComplianceReport:
        """Review document with full audit trail."""

        # Check permissions
        if not self.rbac.can_review(user, document):
            raise PermissionDenied("User lacks review permissions")

        # Redact PII before LLM processing
        redacted_doc = self.pii_handler.redact(document)

        # Log the review initiation
        review_id = await self.audit_log.log_event(
            event_type="review_started",
            user_id=user.id,
            document_hash=hash(document),
            timestamp=datetime.utcnow()
        )

        try:
            # Perform analysis
            findings = await self._analyze(redacted_doc)

            # Score risk
            risk_score = await self._score_risk(findings)

            # Generate recommendations
            recommendations = await self._recommend(findings)

            # Log completion
            await self.audit_log.log_event(
                event_type="review_completed",
                review_id=review_id,
                findings_count=len(findings),
                risk_score=risk_score
            )

            # High-risk items require human approval
            if risk_score > 0.7:
                return ComplianceReport(
                    findings=findings,
                    risk_score=risk_score,
                    recommendations=recommendations,
                    status="pending_human_review",
                    requires_approval=True
                )

            return ComplianceReport(
                findings=findings,
                risk_score=risk_score,
                recommendations=recommendations,
                status="auto_approved"
            )

        except Exception as e:
            await self.audit_log.log_event(
                event_type="review_failed",
                review_id=review_id,
                error=str(e)
            )
            raise
```

### Audit Log Schema

{/* IMAGE_PLACEHOLDER: Create a database schema diagram showing the compliance_audit_log table structure with all fields, data types, and indexes.
```sql
CREATE TABLE compliance_audit_log (
    id UUID PRIMARY KEY,
    event_type VARCHAR(50) NOT NULL,
    user_id UUID NOT NULL,
    document_hash VARCHAR(64),
    review_id UUID,
    findings_count INTEGER,
    risk_score DECIMAL(3,2),
    error TEXT,
    timestamp TIMESTAMP NOT NULL,
    metadata JSONB
);

-- Index for compliance queries
CREATE INDEX idx_audit_user ON compliance_audit_log(user_id);
CREATE INDEX idx_audit_time ON compliance_audit_log(timestamp);
CREATE INDEX idx_audit_risk ON compliance_audit_log(risk_score);
```

**Why This Schema Matters:**
- **Immutable logs**: Once written, audit logs should never be modified (use append-only storage)
- **Queryable**: Indexes support common compliance queries ("Show me all high-risk reviews by user X")
- **Retention**: Plan for 7+ years of retention (regulatory requirement in many industries)
- **JSONB metadata**: Flexible storage for additional context without schema changes

## 74.5 Enterprise Architecture Patterns

{/* IMAGE_PLACEHOLDER: Create an architectural diagram showing the three enterprise patterns as interconnected systems: 1) Fallback Chains (showing GPT-4 → Claude → Local LLM → Rules cascade), 2) Cost Controls (showing budget meter and alert thresholds), 3) Approval Workflows (showing request → notify → wait → approve/reject flow). Use architectural blueprint style with clean lines, icons, and professional color scheme. Show how these patterns work together in an enterprise system. */}

### Pattern 1: Fallback Chains

**The Analogy:** Think of fallback chains like a hospital's power system: primary power from the grid, backup generator if that fails, battery backup if that fails, and manual procedures as the final fallback. Your agent needs the same resilience.

```python
class FallbackChain:
    """Chain of fallback options for reliability."""

    def __init__(self, primary, *fallbacks):
        self.chain = [primary] + list(fallbacks)

    async def execute(self, *args, **kwargs):
        last_error = None

        for handler in self.chain:
            try:
                return await handler(*args, **kwargs)
            except Exception as e:
                last_error = e
                continue

        raise last_error

# Usage
agent = FallbackChain(
    GPT4Agent(),      # Primary
    ClaudeAgent(),    # Fallback 1
    LocalLLMAgent(),  # Fallback 2
    RuleBasedAgent()  # Final fallback (no LLM)
)
```

### Pattern 2: Cost Controls

{/* IMAGE_PLACEHOLDER: Create an interactive-looking cost control dashboard showing: a daily budget meter (like a fuel gauge), current spend vs. budget, alert threshold line at 80%, and a cost breakdown by API calls. Include visual indicators for "safe" (green), "warning" (yellow), and "exceeded" (red) states. Make it look like a real-time monitoring dashboard that would alert DevOps teams. */}

**Why This Matters:** Without cost controls, a single bug or malicious actor can generate thousands of dollars in API costs overnight. One company reported a $50K bill from a runaway loop that ran for 6 hours.

```python
class CostController:
    """Prevent runaway API costs."""

    def __init__(self, daily_budget: float, alert_threshold: float = 0.8):
        self.daily_budget = daily_budget
        self.alert_threshold = alert_threshold
        self.daily_spend = 0.0

    async def check_budget(self, estimated_cost: float) -> bool:
        if self.daily_spend + estimated_cost > self.daily_budget:
            await self._alert("Budget exceeded")
            return False

        if self.daily_spend > self.daily_budget * self.alert_threshold:
            await self._alert("Approaching budget limit")

        return True

    def record_spend(self, actual_cost: float):
        self.daily_spend += actual_cost
```

```python
class ApprovalWorkflow:

    async def request_approval(
        self,
        action: str,
        context: dict,
        approvers: list[str]
    ) -> ApprovalResult:

        # Create approval request
        request = await self.db.create_approval_request(
```
