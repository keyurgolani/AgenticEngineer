## What is a Router Agent?

A **router agent** is like a traffic controller for your AI workflows. It examines the input and routes execution to different specialized nodes based on the content. This is one of the most common patterns in production agent systems.

## The Router Pattern

The router pattern has three key components:

<ConceptVisual
  image="/images/day_14_02_router_components_gears_1769029100822.png"
  caption="Anatomy of a Router: Analyze (Router Node) → Decide (Function) → Act (Handler Nodes)."
  alt="Diagram showing router components as connected gears"
/>

| Component            | Purpose                                  | Example                           |
| :------------------- | :--------------------------------------- | :-------------------------------- |
| **Router Node**      | Analyzes input and sets routing decision | Checks if input contains "search" |
| **Routing Function** | Reads state and returns next node name   | Returns "search" or "chat"        |
| **Handler Nodes**    | Specialized processors for each route    | SearchHandler, ChatHandler        |

## Building the Router

Let's build a simple router step by step. First, install LangGraph if you haven't:

```bash
pip install langgraph
```

### Step 1: Define the State

```python
from typing import TypedDict, Literal
from langgraph.graph import StateGraph, START, END

class AgentState(TypedDict):
    """State schema for our router agent."""
    input: str           # User's input message
    decision: str        # Routing decision or final response
```

### Step 2: Create the Router Node

The router examines the input and sets a routing decision:

```python
def router_node(state: AgentState) -> dict:
    """Analyze input and decide which handler to use."""
    user_input = state["input"].lower()

    if "search" in user_input or "find" in user_input:
        return {"decision": "search"}
    elif "hello" in user_input or "hi" in user_input:
        return {"decision": "chat"}
    else:
        return {"decision": "default"}
```

<Callout type="tip">
  **Production Tip:** In real applications, you'd use an LLM to classify intent
  instead of keyword matching. This simple example demonstrates the pattern
  without API costs.
</Callout>

### Step 3: Create Handler Nodes

Each handler processes its specific type of request:

```python
def search_node(state: AgentState) -> dict:
    """Handle search requests."""
    query = state["input"]
    # In production, this would call a search API
    return {"decision": f"🔍 Searching for: {query}"}

def chat_node(state: AgentState) -> dict:
    """Handle chat/greeting requests."""
    return {"decision": "👋 Hello! How can I help you today?"}

def default_node(state: AgentState) -> dict:
    """Handle unrecognized requests."""
    return {"decision": "🤔 I'm not sure how to help with that. Try asking me to search for something!"}
```

### Step 4: Create the Routing Function

This function reads the state and returns the name of the next node:

```python
def route_decision(state: AgentState) -> Literal["search", "chat", "default"]:
    """Determine which handler to route to based on the decision."""
    decision = state.get("decision", "default")

    if decision == "search":
        return "search"
    elif decision == "chat":
        return "chat"
    else:
        return "default"
```

### Step 5: Build the Graph

Now we wire everything together:

```python
# Initialize the graph
workflow = StateGraph(AgentState)

# Add all nodes
workflow.add_node("router", router_node)
workflow.add_node("search", search_node)
workflow.add_node("chat", chat_node)
workflow.add_node("default", default_node)

# Set entry point: START -> router
workflow.add_edge(START, "router")

# Add conditional edges from router to handlers
workflow.add_conditional_edges(
    "router",           # Source node
    route_decision,     # Routing function
    {                   # Mapping of return values to node names
        "search": "search",
        "chat": "chat",
        "default": "default"
    }
)

# All handlers lead to END
workflow.add_edge("search", END)
workflow.add_edge("chat", END)
workflow.add_edge("default", END)

# Compile the graph
app = workflow.compile()
```

## Complete Working Code

Here's the full implementation you can run:

```python
"""router.py - A simple LangGraph router agent"""
from typing import TypedDict, Literal
from langgraph.graph import StateGraph, START, END


class AgentState(TypedDict):
    """State schema for our router agent."""
    input: str
    decision: str


def router_node(state: AgentState) -> dict:
    """Analyze input and decide which handler to use."""
    user_input = state["input"].lower()

    if "search" in user_input or "find" in user_input:
        return {"decision": "search"}
    elif "hello" in user_input or "hi" in user_input:
        return {"decision": "chat"}
    else:
        return {"decision": "default"}


def search_node(state: AgentState) -> dict:
    """Handle search requests."""
    return {"decision": f"🔍 Searching for: {state['input']}"}


def chat_node(state: AgentState) -> dict:
    """Handle chat/greeting requests."""
    return {"decision": "👋 Hello! How can I help you today?"}


def default_node(state: AgentState) -> dict:
    """Handle unrecognized requests."""
    return {"decision": "🤔 I'm not sure how to help with that."}


def route_decision(state: AgentState) -> Literal["search", "chat", "default"]:
    """Determine which handler to route to."""
    decision = state.get("decision", "default")
    if decision == "search":
        return "search"
    elif decision == "chat":
        return "chat"
    return "default"


# Build the graph
workflow = StateGraph(AgentState)

workflow.add_node("router", router_node)
workflow.add_node("search", search_node)
workflow.add_node("chat", chat_node)
workflow.add_node("default", default_node)

workflow.add_edge(START, "router")
workflow.add_conditional_edges("router", route_decision, {
    "search": "search",
    "chat": "chat",
    "default": "default"
})
workflow.add_edge("search", END)
workflow.add_edge("chat", END)
workflow.add_edge("default", END)

app = workflow.compile()


if __name__ == "__main__":
    test_inputs = [
        "I want to search for cats",
        "Hello there!",
        "Find me some Python tutorials",
        "What's the weather like?",
    ]

    for test_input in test_inputs:
        result = app.invoke({"input": test_input})
        print(f"Input: {test_input!r}")
        print(f"Response: {result['decision']}")
        print("---")
```

## Adding LLM-Based Routing

For production, use an LLM to classify intent:

```python
from openai import OpenAI

client = OpenAI()

def llm_router_node(state: AgentState) -> dict:
    """Use LLM to classify user intent."""
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {
                "role": "system",
                "content": """Classify the user's intent into one of these categories:
- search: User wants to find or look up information
- chat: User is greeting or making small talk
- default: Anything else

Respond with only the category name."""
            },
            {"role": "user", "content": state["input"]}
        ],
        temperature=0
    )

    decision = response.choices[0].message.content.strip().lower()
    return {"decision": decision}
```

<Callout type="warning">
  **Cost Consideration:** LLM-based routing adds latency and cost. For
  high-volume applications, consider: - Caching common classifications - Using
  smaller/faster models for routing (e.g., `gpt-4o-mini`) - Hybrid approach:
  keyword matching first, LLM for ambiguous cases - Embedding-based semantic
  routing (see below)
</Callout>

## Semantic Routing with Embeddings

For production systems with many routes, **embedding-based routing** offers the best balance of accuracy and speed:

<ConceptVisual
  image="/images/day_14_04_routing_approaches_comparison_1769029160691.png"
  caption="Routing Strategies Compared: Semantic routing offers the best balance of accuracy, speed, and cost."
  alt="Comparison of keyword, LLM, and semantic routing approaches"
/>

```python
from openai import OpenAI
import numpy as np
from typing import Literal

client = OpenAI()

# Define route descriptions (embed these once at startup)
ROUTES = {
    "search": "User wants to find information, look up data, or search for something",
    "chat": "User is greeting, making small talk, or having a casual conversation",
    "calculate": "User wants to perform math, compute numbers, or do calculations",
    "code": "User wants help with programming, debugging, or writing code",
}

def get_embedding(text: str) -> list[float]:
    """Get embedding for text."""
    response = client.embeddings.create(
        model="text-embedding-3-small",
        input=text
    )
    return response.data[0].embedding

def cosine_similarity(a: list[float], b: list[float]) -> float:
    """Calculate cosine similarity between two vectors."""
    a, b = np.array(a), np.array(b)
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

# Pre-compute route embeddings (do this once at startup)
route_embeddings = {
    route: get_embedding(description)
    for route, description in ROUTES.items()
}

def semantic_router(user_input: str) -> str:
    """Route based on semantic similarity."""
    input_embedding = get_embedding(user_input)

    similarities = {
        route: cosine_similarity(input_embedding, emb)
        for route, emb in route_embeddings.items()
    }

    best_route = max(similarities, key=similarities.get)
    confidence = similarities[best_route]

    # Fall back to default if confidence is low
    if confidence < 0.3:
        return "default"

    return best_route


# Use in LangGraph
def semantic_router_node(state: AgentState) -> dict:
    """Route using embeddings."""
    route = semantic_router(state["input"])
    return {"decision": route}
```

<Callout type="success">
  **Semantic Routing Benefits:** - **Fast**: Single embedding call vs full LLM
  inference - **Accurate**: Understands meaning, not just keywords -
  **Scalable**: Add new routes by adding descriptions - **Cost-effective**:
  Embedding API is ~100x cheaper than chat completions
</Callout>

## Cost-Aware Model Routing

One of the most powerful applications of routing is **cost optimization**. Route simple queries to cheaper models and complex ones to more capable (expensive) models:

<ConceptVisual
  image="/images/day_14_05_cost_aware_routing_tree_1769029183069.png"
  caption="Cost-Aware Routing: Save 40-60% by routing simple queries to cheaper models."
  alt="Infographic decision tree for cost-optimized routing"
/>

```python
from openai import OpenAI
from typing import Literal

# Define model tiers with costs
MODEL_TIERS = {
    "fast": {"model": "gpt-4o-mini", "cost_per_1k": 0.00015},
    "balanced": {"model": "gpt-4o", "cost_per_1k": 0.0025},
    "powerful": {"model": "claude-sonnet-4-20250514", "cost_per_1k": 0.003},
}

def classify_complexity(query: str) -> Literal["fast", "balanced", "powerful"]:
    """Classify query complexity for model routing."""
    # Simple heuristics - in production, use an embedding classifier
    query_lower = query.lower()

    # Complex indicators
    complex_keywords = ["analyze", "compare", "explain why", "debug", "architect"]
    if any(kw in query_lower for kw in complex_keywords):
        return "powerful"

    # Medium complexity
    medium_keywords = ["summarize", "write", "create", "help me"]
    if any(kw in query_lower for kw in medium_keywords):
        return "balanced"

    # Simple queries
    return "fast"


class CostAwareRouter:
    """Router that optimizes for cost while maintaining quality."""

    def __init__(self):
        self.client = OpenAI()
        self.total_cost = 0.0

    def route_and_execute(self, query: str) -> dict:
        tier = classify_complexity(query)
        model_config = MODEL_TIERS[tier]

        response = self.client.chat.completions.create(
            model=model_config["model"],
            messages=[{"role": "user", "content": query}]
        )

        # Track costs
        tokens_used = response.usage.total_tokens
        cost = (tokens_used / 1000) * model_config["cost_per_1k"]
        self.total_cost += cost

        return {
            "response": response.choices[0].message.content,
            "model_used": model_config["model"],
            "tier": tier,
            "cost": cost
        }
```

<Callout type="success">
  **Real-World Impact:** Organizations implementing intelligent model routing
  report **40-63% cost reductions** while maintaining quality. The key is
  routing ~70% of simple queries to fast/cheap models.
</Callout>

## Multi-Model Routing with Fallbacks

Production systems need fallback logic when primary models fail:

<ConceptVisual
  image="/images/day_14_06_resilient_routing_flowchart_1769029203649.png"
  caption="Resilient Routing: Automatic fallbacks ensure reliability when primary models fail."
  alt="Flowchart showing resilient multi-model routing logic"
/>

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class MultiModelState(TypedDict):
    input: str
    response: str
    model_used: str
    attempts: int
    error: str | None

def primary_model_node(state: MultiModelState) -> dict:
    """Try the primary (preferred) model first."""
    try:
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": state["input"]}],
            timeout=10
        )
        return {
            "response": response.choices[0].message.content,
            "model_used": "gpt-4o",
            "error": None
        }
    except Exception as e:
        return {"error": str(e), "attempts": state.get("attempts", 0) + 1}

def fallback_model_node(state: MultiModelState) -> dict:
    """Fallback to a different model/provider."""
    try:
        # Could be a different provider (Anthropic, local Ollama, etc.)
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": state["input"]}]
        )
        return {
            "response": response.choices[0].message.content,
            "model_used": "gpt-4o-mini (fallback)",
            "error": None
        }
    except Exception as e:
        return {"error": str(e), "response": "All models failed."}

def should_fallback(state: MultiModelState) -> str:
    """Decide whether to use fallback based on error state."""
    if state.get("error") and state.get("attempts", 0) < 3:
        return "fallback"
    return "end"

# Build fallback graph
workflow = StateGraph(MultiModelState)
workflow.add_node("primary", primary_model_node)
workflow.add_node("fallback", fallback_model_node)

workflow.add_edge(START, "primary")
workflow.add_conditional_edges("primary", should_fallback, {
    "fallback": "fallback",
    "end": END
})
workflow.add_edge("fallback", END)

app = workflow.compile()
```

<Callout type="tip">
  **Production Fallback Strategies:** - **Provider diversity**: Primary on
  OpenAI, fallback on Anthropic - **Local fallback**: Cloud primary, Ollama
  fallback for resilience - **Graceful degradation**: Powerful model → smaller
  model → cached response
</Callout>

def calculate_node(state: AgentState) -> dict:
    """Handle calculation requests."""
    import re
    import ast

    # Extract numbers and operators from input
    user_input = state["input"]

    # Find mathematical expression (simple pattern)
    # In production, use a proper math parser
    match = re.search(r'[\d\+\-\*\/\.\(\)\s]+', user_input)
    if match:

        try:
            # Safe evaluation using ast.literal_eval for simple cases

            pass
