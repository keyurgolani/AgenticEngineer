### Tier 1: Production-Ready

These frameworks have proven themselves in production environments across thousands of applications. Each excels in different scenarios—choosing the right one depends on your specific needs.

| Project                                                | Stars | Description                         | Best For               |
| :----------------------------------------------------- | :---- | :---------------------------------- | :--------------------- |
| [LangChain](https://github.com/langchain-ai/langchain) | 100k+ | The standard framework for LLM apps | General-purpose agents |
| [LangGraph](https://github.com/langchain-ai/langgraph) | 10k+  | Stateful, cyclic agent workflows    | Complex orchestration  |
| [CrewAI](https://github.com/crewAIInc/crewAI)          | 25k+  | Role-based multi-agent systems      | Business workflows     |
| [AutoGen](https://github.com/microsoft/autogen)        | 40k+  | Conversational multi-agent          | Research, coding       |
| [LlamaIndex](https://github.com/run-llama/llama_index) | 40k+  | Data framework for LLMs             | RAG applications       |

<Callout type="info">
  **Framework Selection Analogy:** Think of frameworks like transportation
  modes. LangChain is the highway system (connects everything), LangGraph is the
  railway network (structured routes with stations), CrewAI is the corporate
  shuttle (organized teams), AutoGen is the conversation pit stop
  (back-and-forth dialogue), and LlamaIndex is the data pipeline (moves
  information efficiently).
</Callout>

### Vector Databases

Vector databases are the memory systems for AI agents. They store embeddings (numerical representations of text, images, or other data) and enable semantic search—finding information by meaning rather than exact keywords.

| Project                                           | Type           | Best For                 |
| :------------------------------------------------ | :------------- | :----------------------- |
| [ChromaDB](https://github.com/chroma-core/chroma) | Embedded       | Development, small scale |
| [LanceDB](https://github.com/lancedb/lancedb)     | Embedded       | Local-first, multimodal  |
| [Qdrant](https://github.com/qdrant/qdrant)        | Server         | Production, filtering    |
| [Weaviate](https://github.com/weaviate/weaviate)  | Server         | Hybrid search            |
| [Milvus](https://github.com/milvus-io/milvus)     | Distributed    | Large scale              |
| [pgvector](https://github.com/pgvector/pgvector)  | PostgreSQL ext | Existing Postgres        |

<Callout type="tip">
  **Choosing a Vector DB:** Start with ChromaDB or LanceDB for local development
  (they run in-process, no separate server needed). Move to Qdrant or Weaviate
  when you need production features like filtering, multi-tenancy, and
  horizontal scaling. Use pgvector if you already have PostgreSQL and want to
  avoid adding another database.
</Callout>

### Inference Engines

Local LLM deployment offers privacy, cost control, and low latency. Based on recent benchmarks, vLLM provides significantly better throughput than Ollama for production scenarios (up to 3x higher performance), while Ollama excels at ease of use for development and prototyping.

| Project                                                         | Description               | Best For             |
| :-------------------------------------------------------------- | :------------------------ | :------------------- |
| [Ollama](https://github.com/ollama/ollama)                      | Easy local LLM deployment | Getting started      |
| [vLLM](https://github.com/vllm-project/vllm)                    | High-throughput serving   | Production           |
| [llama.cpp](https://github.com/ggerganov/llama.cpp)             | CPU inference             | Resource-constrained |
| [TGI](https://github.com/huggingface/text-generation-inference) | HuggingFace serving       | HF ecosystem         |
| [LM Studio](https://lmstudio.ai)                                | GUI for local LLMs        | Non-technical users  |

<Callout type="info">
  **Deployment Strategy:** Use Ollama for development and experimentation
  (simple CLI, great model library). Switch to vLLM for production deployments
  where you need to serve multiple concurrent users with high throughput. Use
  llama.cpp when you need to run models on CPU-only machines or edge devices.
</Callout>

It features a 128K token context window and was trained on over 15 trillion tokens.

<Callout type="success">
  **Llama 3.3 Highlights:** With 70B parameters, Llama 3.3 delivers exceptional
  value—matching 405B model performance at a fraction of the cost. Key features

  multilingual support (8+ languages), strong math and coding capabilities, and
  affordable inference ($0.10 per million input tokens, $0.40 per million output
  tokens). Perfect for production deployments where cost and efficiency matter.

### Code Execution

When agents write and execute code, sandboxing is critical for security. These tools provide isolated environments where code can run safely without risking your infrastructure.

| Project                                                           | Description            |
| :---------------------------------------------------------------- | :--------------------- |
| [E2B](https://github.com/e2b-dev/e2b)                             | Cloud sandboxes for AI |
| [Modal](https://modal.com)                                        | Serverless compute     |
| [Firecracker](https://github.com/firecracker-microvm/firecracker) | MicroVMs               |
| [gVisor](https://github.com/google/gvisor)                        | Container sandbox      |

<Callout type="warning">
  **Security First:** Never execute agent-generated code directly on your
  production systems. Always use sandboxing. E2B provides ready-to-use cloud
  sandboxes specifically designed for AI agents. For self-hosted solutions,
  Firecracker (used by AWS Lambda) or gVisor (used by Google Cloud Run) provide
  strong isolation guarantees.
</Callout>

### How to Start

Contributing to open source accelerates your learning, builds your reputation, and gives back to the community. Here's your roadmap:

1. **Find a project** that aligns with your interests
2. **Read the contributing guide** (CONTRIBUTING.md)
3. **Start with documentation** or small bug fixes
4. **Join the community** (Discord, Slack, GitHub Discussions)
5. **Be patient and persistent**

<Callout type="success">
  **Career Impact:** Open source contributions are visible proof of your skills.
  Hiring managers can see your code, communication style, and ability to
  collaborate. Many developers land jobs through connections made in open source
  communities. Plus, you'll learn from code reviews by experienced
  maintainers—it's like free mentorship.
</Callout>

### High-Impact Contributions

| Type          | Impact                         |
| :------------ | :----------------------------- |
| Documentation | High - helps everyone          |
| Bug fixes     | Medium - improves stability    |
| New features  | High - but requires discussion |
| Tests         | Medium - improves reliability  |
| Examples      | High - helps adoption          |

### Projects Seeking Contributors

- **LangChain**: Always needs documentation and examples
- **CrewAI**: Growing fast, needs tools and integrations
- **MCP Servers**: Many services need MCP servers
- **Evaluation**: Benchmarks need more test cases
