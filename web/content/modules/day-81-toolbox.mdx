### Basic ReAct Agent

```python
"""Minimal ReAct agent template."""
from openai import OpenAI
import json

client = OpenAI()

SYSTEM_PROMPT = """You are a helpful assistant with tools.

Available tools:
- search(query): Search the web
- calculate(expression): Evaluate math

Respond in JSON:
{"thought": "...", "action": "tool_name", "action_input": {...}}
or
{"thought": "...", "action": "final_answer", "action_input": "..."}
"""

def run_agent(user_input: str, max_iterations: int = 5) -> str:
    """Run a basic ReAct agent loop.
    
    This is the simplest production-ready agent pattern. The agent:
    1. Thinks about what to do (Reasoning)
    2. Takes an action (Acting)
    3. Observes the result
    4. Repeats until it has a final answer
    """
    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {"role": "user", "content": user_input}
    ]

    for iteration in range(max_iterations):
        response = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=messages,
            temperature=0.1
        )

        content = response.choices[0].message.content
        parsed = json.loads(content)

        if parsed["action"] == "final_answer":
            return parsed["action_input"]

        # Execute tool and continue
        result = execute_tool(parsed["action"], parsed["action_input"])
        messages.append({"role": "assistant", "content": content})
        messages.append({"role": "user", "content": f"Observation: {result}"})

    return "Max iterations reached"
```

<Callout type="tip">
  **When to Use:** This template is perfect for simple task automation, Q&A with tools, or prototyping new agent ideas. It's the "Hello World" of production agents.
</Callout>

### LangGraph Workflow Template

{/* IMAGE_PLACEHOLDER: Animated flow diagram showing state transitions in a LangGraph workflow. Visualize nodes (A, B) as circles with state flowing between them, and a router diamond deciding the path. Include arrows showing the flow from START to nodes to END. Style: Clean flowchart with subtle animations showing state progression. Placement: Right before the code block */}

```python
"""LangGraph workflow template."""
from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated, List
import operator

class AgentState(TypedDict):
    """State that flows through the graph.
    
    Think of this as a package being passed between workers on an
    assembly line—each worker (node) adds something to the package.
    """
    messages: Annotated[List, operator.add]
    current_step: str

def node_a(state: AgentState) -> dict:
    """First processing step."""
    return {"messages": ["Completed step A"], "current_step": "b"}

def node_b(state: AgentState) -> dict:
    """Second processing step."""
    return {"messages": ["Completed step B"], "current_step": "done"}

def router(state: AgentState) -> str:
    """Decide where to go next based on state."""
    if state["current_step"] == "done":
        return END
    return state["current_step"]

# Build graph
workflow = StateGraph(AgentState)
workflow.add_node("a", node_a)
workflow.add_node("b", node_b)
workflow.add_edge(START, "a")
workflow.add_conditional_edges("a", router)
workflow.add_conditional_edges("b", router)

app = workflow.compile()
result = app.invoke({"messages": [], "current_step": "a"})
```

<Callout type="tip">
  **When to Use:** LangGraph shines for complex workflows with branching logic, human-in-the-loop patterns, or when you need to persist and resume agent state. It's the production choice for sophisticated agents.
</Callout>

### MCP Server Template

{/* IMAGE_PLACEHOLDER: Diagram showing MCP server architecture - a server box in the center with multiple tool functions as plugins/modules connecting to it, and client applications (Claude Desktop, custom agents) connecting from the other side.
```python
"""MCP server template.

MCP (Model Context Protocol) servers expose tools and resources to AI agents.
Think of them as API servers specifically designed for AI consumption.
"""
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("my-server")

@mcp.tool()
async def my_tool(param1: str, param2: int = 10) -> str:
    """Description of what this tool does.

    Args:
        param1: Description of param1
        param2: Description of param2 (default: 10)

    Returns:
        Description of return value
    """
    return f"Result: {param1}, {param2}"

@mcp.resource("myserver://data")
async def get_data() -> str:
    """Get some data.
    
    Resources are read-only data sources that agents can access.
    Use them for configuration, documentation, or reference data.
    """
    return "Data content here"

if __name__ == "__main__":
    mcp.run()
```

<Callout type="tip">
  **When to Use:** Build MCP servers to expose your internal tools, databases, or APIs to AI agents. They're especially powerful for creating reusable tool libraries that work across different agent frameworks.
</Callout>

### RAG Pipeline Template

{/* IMAGE_PLACEHOLDER: Visual flow of RAG pipeline - documents going into a chunking process, then embeddings being generated and stored in a vector database (shown as a grid of vectors), then a query coming in, similarity search happening (highlight matching vectors), and context being retrieved and sent to LLM. Style: Data flow diagram with icons. Placement: Right before the code block */}

```python
"""RAG pipeline template.

RAG (Retrieval-Augmented Generation) combines vector search with LLM generation.
It's like giving your agent a searchable library of knowledge.
"""
import chromadb
from openai import OpenAI

client = OpenAI()
chroma = chromadb.Client()
collection = chroma.create_collection("docs")

def ingest(texts: list[str], ids: list[str]):
    """Add documents to the knowledge base.
    
    In production, you'd also:
    - Chunk large documents
    - Add metadata for filtering
    - Handle updates and deletions
    """
    collection.add(documents=texts, ids=ids)

def query(question: str, n_results: int = 3) -> str:
    """Answer a question using retrieved context.
    
    The magic of RAG: the LLM only sees relevant context,
    not your entire document collection.
    """
    results = collection.query(query_texts=[question], n_results=n_results)
    context = "\n\n".join(results["documents"][0])

    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {"role": "system", "content": f"Answer based on context:\n{context}"},
            {"role": "user", "content": question}
        ]
    )
    return response.choices[0].message.content
```

<Callout type="tip">
  **When to Use:** RAG is essential when your agent needs to work with large knowledge bases, documentation, or frequently updated information. It's more cost-effective than fine-tuning and easier to update.
</Callout>

## 81.5 Debugging Cheatsheet

{/* IMAGE_PLACEHOLDER: Visual debugging dashboard showing common agent issues as diagnostic panels - one panel showing an infinite loop with a circuit breaker, another showing token overflow with a gauge, another showing tool errors with a wrench icon. Style: Dashboard/monitoring interface aesthetic. Placement: Right after section heading */}

**Troubleshooting Guide:** When things go wrong (and they will), start here. These are the issues every agent developer encounters.

### Common Issues and Solutions

| Issue               | Cause                    | Solution                                     |
| :------------------ | :----------------------- | :------------------------------------------- |
| Agent loops forever | No termination condition | Add max_iterations, check for "final_answer" |
| Context too long    | Accumulating history     | Implement summarization, use sliding window  |
| Tool not found      | Wrong tool name          | Check tool registration, use exact names     |
| JSON parse error    | LLM output malformed     | Add retry logic, use structured output       |
| Rate limited        | Too many API calls       | Add exponential backoff, batch requests      |
| Memory leak         | Unbounded state growth   | Implement memory compaction                  |

## 81.6 Performance Optimization

{/* IMAGE_PLACEHOLDER: Performance optimization as a race car being tuned - show three pit stops: "Token Efficiency" (removing excess baggage), "Parallel Execution" (multiple engines), and "Caching" (fuel efficiency). **Speed and Cost Optimization:** These patterns can reduce your agent's cost by 10x and latency by 5x. They're the difference between a prototype and a production system.

### Token Efficiency

```python
# Bad: Sending full history every time
messages = full_conversation_history  # Could be 100k tokens!

# Good: Summarize and truncate
def optimize_context(messages, max_tokens=4000):
    """Optimize context window to reduce costs.
    
    This is like summarizing a long conversation before continuing it.
    You keep the important parts and compress the rest.
    """
    # Keep system prompt
    system = messages[0]

    # Keep last N messages (recent context is most important)
    recent = messages[-5:]

    # Summarize the rest
    if len(messages) > 6:
        middle = messages[1:-5]
        summary = summarize(middle)
        return [system, {"role": "system", "content": f"Summary: {summary}"}] + recent

    return messages
```

<Callout type="info">
  **Real Impact:** One production team reduced their GPT-4 costs from $5,000/month to $500/month just by implementing context optimization. The agent quality actually improved because it focused on relevant information.
</Callout>

### Parallel Tool Execution

```python
import asyncio

async def execute_tools_parallel(tool_calls: list) -> list:
    """Execute multiple tool calls in parallel.
    
    Why wait for tools sequentially when they're independent?
    This is like having multiple workers instead of one.
    """
    tasks = [execute_tool(call) for call in tool_calls]
    return await asyncio.gather(*tasks)

# Example: Search multiple sources simultaneously
async def multi_source_search(query: str):
    """Search web, docs, and database in parallel."""
    results = await asyncio.gather(
        search_web(query),
        search_docs(query),
        search_database(query)
    )
    return combine_results(results)
```

<Callout type="tip">
  **Performance Gain:** Parallel execution can reduce agent response time from 15 seconds to 3 seconds when calling multiple independent tools. Always look for opportunities to parallelize.
</Callout>

### Caching

```python
from functools import lru_cache
import hashlib

@lru_cache(maxsize=1000)
def cached_embedding(text: str) -> list:
    """Cache embeddings to avoid redundant API calls.
    
    Embeddings for the same text never change, so cache them!
    This can save thousands of API calls.
    """
    return get_embedding(text)

def cache_key(query: str, context: str) -> str:
    """Generate cache key for LLM responses.
    
    For deterministic queries (temperature=0), you can cache
    the entire LLM response. Great for FAQ-style agents.
    """
    return hashlib.md5(f"{query}:{context}".encode()).hexdigest()

# Redis-based cache for distributed systems
import redis
r = redis.Redis()

def cached_llm_call(prompt: str, ttl: int = 3600):
    """Cache LLM responses in Redis."""
    key = f"llm:{hashlib.md5(prompt.encode()).hexdigest()}"
    cached = r.get(key)
    if cached:
        return cached.decode()
    
    response = call_llm(prompt)
    r.setex(key, ttl, response)
    return response
```

<Callout type="info">
  **Caching Strategy:** Cache embeddings aggressively (they never change), cache LLM responses cautiously (only for deterministic, repeated queries), and always set appropriate TTLs.
</Callout>

## 81.7 Security Checklist

{/* IMAGE_PLACEHOLDER: Security checklist as a fortress with multiple defensive layers - show input validation as the outer wall, sandboxed execution as the moat, data encryption as the vault, and monitoring as watchtowers. Style: Medieval fortress meets modern security. Placement: Right after section heading */}

**Defense in Depth:** Security isn't optional for production agents. This checklist covers the critical controls that prevent the most common vulnerabilities.

```markdown
## Pre-Deployment Security Checklist

### Input Validation

- [ ] Sanitize all user inputs (remove/escape special characters)
- [ ] Implement prompt injection detection (check for system prompt overrides)
- [ ] Validate tool parameters (type checking, range validation)
- [ ] Set maximum input lengths (prevent DoS via large inputs)

### Execution Security

- [ ] Use sandboxed code execution (E2B/Docker/gVisor)
- [ ] Implement resource limits (CPU, memory, time, network)
- [ ] Disable network access for untrusted code
- [ ] Whitelist allowed operations (file access, system calls)

### Data Protection

- [ ] Never log sensitive data (API keys, PII, passwords)
- [ ] Encrypt data at rest and in transit (TLS, AES-256)
- [ ] Implement data retention policies (auto-delete after N days)
- [ ] Use secrets management (Vault, AWS Secrets Manager)

### Access Control

- [ ] Use least-privilege service accounts (minimal permissions)
- [ ] Rotate API keys regularly (automated rotation)
- [ ] Implement rate limiting (per-user, per-IP, per-endpoint)
- [ ] Add authentication and authorization (OAuth, JWT)

### Monitoring

- [ ] Log all agent actions (tool calls, decisions, errors)
- [ ] Set up anomaly detection (unusual patterns, high costs)
- [ ] Create incident response playbook (who to call, what to do)
- [ ] Monitor for prompt injection attempts (alert on suspicious patterns)
```

<Callout type="warning">
  **Critical:** The most common agent security breach is prompt injection leading to unauthorized tool execution. Always validate that tool calls match the user's intent, not just the LLM's output.
</Callout>
