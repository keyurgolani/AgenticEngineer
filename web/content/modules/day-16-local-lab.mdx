**Ollama** is the simplest way to run open-source LLMs locally. It handles model downloads, quantization, and provides an OpenAI-compatible API out of the box.

Think of Ollama as "Docker for LLMs"—it abstracts away the complexity of model formats, GPU drivers, and inference engines, giving you a simple CLI and API to work with.

### macOS

```bash
brew install ollama
```

### Linux

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

### Windows

Download the installer from [ollama.com/download](https://ollama.com/download) or use:

```powershell
winget install Ollama.Ollama
```

### Verify Installation

```bash
ollama --version
# Should output: ollama version 0.x.x
```

Ollama uses a Docker-like pull system for models. Let's start with **Llama 3.3**, Meta's widely used open-weight model that offers excellent performance for agent development:

```bash
# Pull the 70B model (recommended for quality)
ollama pull llama3.3

# Or pull the smaller 8B model for faster iteration
ollama pull llama3.2
```

<Callout type="tip">
  **Model Sizing Guide for Standard Models:** - **7-8B models**: 8GB RAM
  minimum, good for most development tasks - **13B models**: 16GB RAM
  recommended - **70B models**: 40GB+ RAM, enterprise-grade quality - Quantized
  versions (Q4, Q5) reduce memory requirements by ~50% **For Mixture-of-Experts
  (MoE) Models:** - Only active parameters load into memory during inference -
  Llama 4 Scout (17B active / 109B total): ~24GB RAM for Q4 quantization - Llama
  4 Maverick (17B active / 400B total): ~48GB+ RAM recommended
</Callout>

### Popular Models for Agent Development

| Model                | Architecture  | Active Params | Best For                   | Pull Command                  |
| :------------------- | :------------ | :------------ | :------------------------- | :---------------------------- |
| **Llama 3.3**        | Dense         | 70B           | General, high quality      | `ollama pull llama3.3`        |
| **Llama 3.2**        | Dense         | 3B / 8B       | Fast iteration, edge       | `ollama pull llama3.2`        |
| **Llama 4 Scout**    | MoE (16 exp)  | 17B / 109B    | Long context (10M tokens)  | `ollama pull llama4`          |
| **Llama 4 Maverick** | MoE (128 exp) | 17B / 400B    | High performance reasoning | `ollama pull llama4:maverick` |
| **Qwen 3**           | Dense/MoE     | 0.6B-235B     | Hybrid thinking, coding    | `ollama pull qwen3`           |
| **DeepSeek-R1**      | MoE           | 37B / 671B    | SOTA Reasoning             | `ollama pull deepseek-r1`     |
| **Mistral Large 3**  | MoE (675B)    | 41B / 675B    | Multimodal, 256K context   | `ollama pull mistral-large`   |
| **Mistral Small 3**  | Dense         | 24B           | Efficient, multilingual    | `ollama pull mistral-small`   |

<Callout type="info">
  **Understanding MoE Models:** Mixture-of-Experts models like Llama 4,
  DeepSeek-R1, Qwen 3, and Mistral Large 3 have many total parameters but only
  activate a subset (the "active" parameters) for each token. This means faster
  inference than the total parameter count suggests, but you still need enough
  RAM to load the full model weights. For example, Llama 4 Scout activates only
  17B of its 109B parameters per token.
</Callout>

<Callout type="tip">
  **Qwen 3 Hybrid Thinking:** Qwen 3 models support two modes—**Thinking Mode**
  for step-by-step reasoning on complex problems, and **Non-Thinking Mode** for
  instant responses on simpler queries. This makes them excellent for agent
  development where you need both deep reasoning and fast responses.
</Callout>

Here's the key insight: **Ollama exposes an OpenAI-compatible API**. This means you can use the standard OpenAI Python SDK with local models—just change the base URL.

Think of it like changing a database connection string—your application code stays the same, but you're now talking to a different backend.

### Start the Ollama Server

```bash
# Ollama runs as a background service automatically on install
# If needed, start manually:
ollama serve
```

The API is available at `http://localhost:11434`.

### Python Integration

```python
from openai import OpenAI

# Point to local Ollama server
client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"  # Required by SDK but not used by Ollama
)

response = client.chat.completions.create(
    model="llama3.3",
    messages=[
        {"role": "system", "content": "You are a helpful AI assistant."},
        {"role": "user", "content": "Explain the ReAct pattern in one paragraph."}
    ],
    temperature=0.7,
)

print(response.choices[0].message.content)
```

<Callout type="success">
  **Zero Code Changes Required!** If you have existing code using the OpenAI
  SDK, you only need to change `base_url` to switch between cloud and local
  models. This makes it trivial to develop locally and deploy with cloud APIs.
</Callout>

## 4.5 Native Tool Calling with Ollama

<Mermaid
  chart={`
sequenceDiagram
    participant App
    participant Model
    participant Function
    
    App->>Model: Query + Tool Definitions
    Note right of Model: "What's the weather?"
    
    Model->>Model: Decide to call tool
    Model-->>App: Tool Call: get_weather("Tokyo")
    
    App->>Function: Execute get_weather()
    Function-->>App: Result: "Sunny, 25C"
    
    App->>Model: Tool Output
    Model-->>App: Final Answer: "It's sunny in Tokyo."
`}
  caption="Local Tool Calling: Native function calling support in Ollama enables agentic workflows."
/>

As of Ollama v0.8+, local models support **native tool calling**—the same function calling interface used by OpenAI and Anthropic. This is critical for building agents:

```python
from openai import OpenAI
import json

client = OpenAI(
    base_url="http://localhost:11434/v1",
    api_key="ollama"
)

# Define tools using OpenAI's function calling format
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get the current weather for a location",
            "parameters": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "City name, e.g., 'San Francisco'"
                    }
                },
                "required": ["location"]
            }
        }
    }
]

response = client.chat.completions.create(
    model="llama3.3",
    messages=[{"role": "user", "content": "What's the weather in Tokyo?"}],
    tools=tools,
    tool_choice="auto"
)

# Check if the model wants to call a tool
message = response.choices[0].message
if message.tool_calls:
    tool_call = message.tool_calls[0]
    print(f"Tool: {tool_call.function.name}")
    print(f"Args: {tool_call.function.arguments}")
```

<Callout type="info">
  **Model Support for Tool Calling:** Not all models support tool calling
  equally well. For best results with local tool calling, use: - **Llama 3.3
  70B** — Excellent tool calling accuracy - **Llama 4 Scout/Maverick** — Native
  multimodal + tool calling - **Qwen 3** — Strong function calling with hybrid
  thinking modes - **Mistral Large 3** — Excellent tool use with 256K context
  Smaller models (7B-8B) may struggle with complex tool schemas.
</Callout>

## 4.6 Connecting to Your Agent

Let's integrate a local model with the agent loop from earlier today:

```python
from openai import OpenAI
import json

class LocalAgent:
    """Agent using local Ollama model."""

    def __init__(self, model: str = "llama3.3"):
        self.client = OpenAI(
            base_url="http://localhost:11434/v1",
            api_key="ollama"
        )
        self.model = model
        self.tools = {}

    def register_tool(self, name: str, func, description: str):
        self.tools[name] = {"function": func, "description": description}

    def run(self, user_input: str) -> str:
        """Run the agent loop with local model."""
        system_prompt = self._build_system_prompt()
        messages = [
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": user_input}
        ]

        for _ in range(10):  # Max iterations
            response = self.client.chat.completions.create(
                model=self.model,
                messages=messages,
                temperature=0.1
            )

            content = response.choices[0].message.content
            messages.append({"role": "assistant", "content": content})

            # Parse and execute (simplified)
            if "FINAL ANSWER:" in content:
                return content.split("FINAL ANSWER:")[-1].strip()

            # Continue loop with tool execution...

        return "Max iterations reached."

    def _build_system_prompt(self) -> str:
        tool_docs = "\n".join([
            f"- {name}: {info['description']}"
            for name, info in self.tools.items()
        ])
        return f"""You are a helpful assistant with tools.

Available Tools:
{tool_docs}

Think step by step. When done, respond with FINAL ANSWER: <your answer>"""


# Usage
agent = LocalAgent(model="llama3.3")
result = agent.run("What is 2 + 2?")
print(result)
```

## 4.8 Environment Configuration

For production code, use environment variables to switch between local and cloud:

```python
import os
from openai import OpenAI

def get_llm_client():
    """Get LLM client based on environment."""
    if os.getenv("USE_LOCAL_LLM", "false").lower() == "true":
        return OpenAI(
            base_url="http://localhost:11434/v1",
            api_key="ollama"
        )
    else:
        return OpenAI()  # Uses OPENAI_API_KEY from environment

# In your .env file:
# USE_LOCAL_LLM=true
# OPENAI_API_KEY=sk-...  (for cloud fallback)
```

<Callout type="tip">
  **Development Workflow:** 1. Set `USE_LOCAL_LLM=true` during development 2.
  Test with local models (free, fast, private) 3. Switch to cloud APIs for
  production or when you need stronger models
</Callout>

Route simple queries to cheaper/smaller models, complex ones to larger models:

```python
def route_by_complexity(query: str) -> str:
    """Route queries to appropriate models based on complexity."""
    # Simple heuristics - in production, use an LLM classifier
    word_count = len(query.split())

    if word_count < 20 and "?" not in query:
        return "llama3.2:3b"  # Fast, cheap for simple tasks
    elif "code" in query.lower() or "debug" in query.lower():
        return "qwen3:32b"    # Coding specialist
    else:
        return "llama3.3"     # Full capability for complex reasoning
```

<Callout type="success">
  **Real Impact:** Research shows routing 70% of straightforward queries to
  smaller models yields a **63% cost reduction** while maintaining quality for
  complex tasks.
</Callout>

### Prompt Caching

```python
# Anthropic prefix caching example
response = client.messages.create(
```

| Strategy                          | Savings | Implementation                             |
| :-------------------------------- | :------ | :----------------------------------------- |

## 4.12 Building a Local Chat UI

The CLI is great for testing, but users need a GUI. Because Ollama is OpenAI-compatible, we can build a chat app in < 30 lines of Python using Streamlit:

```python
# app.py
import streamlit as st
from langchain_ollama import OllamaLLM

st.title("Local AI Chat 🦙")

# Initialize model
if "model" not in st.session_state:
    st.session_state.model = OllamaLLM(model="llama3.2")

# Initialize chat history
if "messages" not in st.session_state:
    st.session_state.messages = []

# Display history
for message in st.session_state.messages:
    with st.chat_message(message["role"]):
        st.markdown(message["content"])

# Handle input
if prompt := st.chat_input("Ask me anything..."):
    # Add user message
    st.session_state.messages.append({"role": "user", "content": prompt})
    with st.chat_message("user"):
        st.markdown(prompt)

    # Generate response
    with st.chat_message("assistant"):
        response_placeholder = st.empty()
        full_response = st.session_state.model.invoke(prompt)
        response_placeholder.markdown(full_response)

    # Add assistant message
    st.session_state.messages.append({"role": "assistant", "content": full_response})
```

Run it with:

```bash
pip install streamlit langchain_ollama
streamlit run app.py
```

```yaml
    depends_on:
      - searxng

  searxng:
    image: searxng/searxng:latest
    ports:
      - "8080:8080"
    environment:
      - SEARXNG_BASE_URL=http://localhost:8080
```

This gives you a powerful, private, free alternative to paid AI search engines.
