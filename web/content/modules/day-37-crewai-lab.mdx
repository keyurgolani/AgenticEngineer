### The CrewAI Philosophy

CrewAI models AI collaboration after real-world organizational structures. Rather than abstract pipelines or conversation threads, CrewAI organizes agents into **crews**—teams with distinct roles, goals, and areas of expertise that mirror how human teams tackle complex projects.

This approach provides several advantages:

- **Natural task decomposition**: Complex problems break down into specialist roles
- **Clear accountability**: Each agent has defined responsibilities
- **Intuitive debugging**: You can trace issues to specific team members
- **Scalable patterns**: Add specialists as complexity grows

**Real-World Analogy**: Think of CrewAI like assembling a film production crew. You wouldn't have one person do everything—you'd hire a director (project manager), cinematographer (researcher), screenwriter (writer), and editor (editor). Each specialist brings deep expertise in their domain, and the magic happens when they collaborate. CrewAI brings this same organizational model to AI agents.

```python
from pydantic import BaseModel, Field
from typing import List, Optional

class ResearchFinding(BaseModel):
    """A single research finding with source."""
    fact: str = Field(description="The key fact or insight")
    source: str = Field(description="URL or reference for the source")
    relevance: str = Field(description="Why this is relevant to the topic")

class ResearchBrief(BaseModel):
    """Structured output for research task."""
    topic: str = Field(description="The research topic")
    key_findings: List[ResearchFinding] = Field(description="List of key findings")
    expert_quotes: List[str] = Field(description="Notable expert opinions")
    recent_developments: List[str] = Field(description="Recent news or updates")
    common_questions: List[str] = Field(description="FAQs about the topic")
    recommended_subtopics: List[str] = Field(description="Related topics to cover")

class CompetitorAnalysis(BaseModel):
    """Structured output for competitor analysis."""
    competitors: List[dict] = Field(description="Top competing articles")
    common_themes: List[str] = Field(description="Themes across competitors")
    content_gaps: List[str] = Field(description="What competitors miss")
    opportunities: List[str] = Field(description="Differentiation opportunities")
    recommended_word_count: int = Field(description="Target word count")

class ArticleOutput(BaseModel):
    """Structured output for the final article."""
    title: str = Field(description="SEO-optimized title")
    meta_description: str = Field(description="Meta description for SEO")
    content: str = Field(description="Full article in markdown")
    keywords: List[str] = Field(description="Target keywords")
```

    5. Is engaging and readable

## 37.6 CrewAI Flows: Structured Workflow Orchestration

<Callout type="tip">
  **New in CrewAI:** Flows are a powerful addition that allow you to create
  structured, event-driven workflows. They provide seamless ways to connect
  multiple crews, manage state, and control execution flow with conditional
  logic and persistence.
</Callout>

Flows combine the autonomous collaboration of Crews with structured automation and precise control. They're ideal for complex workflows that need:

- **Conditional logic**: Route execution based on results
- **State management**: Persist data across steps
- **Multiple crews**: Orchestrate several crews in sequence or parallel
- **Error handling**: Graceful recovery and retry logic

### Basic Flow Structure

```python
from crewai.flow.flow import Flow, listen, start, router
from pydantic import BaseModel
from typing import Optional

class ContentState(BaseModel):
    """State that persists across flow steps."""
    topic: str = ""
    research_brief: Optional[str] = None
    draft_article: Optional[str] = None
    final_article: Optional[str] = None
    quality_score: float = 0.0
    iteration_count: int = 0

class ContentCreationFlow(Flow[ContentState]):
    """A flow that orchestrates the content creation process."""

    @start()
    def initialize(self):
        """Entry point - set up the topic."""
        print(f"Starting content creation for: {self.state.topic}")
        return self.state.topic

    @listen(initialize)
    def research_phase(self, topic: str):
        """Run the research crew."""
        research_crew = Crew(
            agents=[researcher, competitor_analyst],
            tasks=[research_task, competitor_task],
            process=Process.sequential
        )

        result = research_crew.kickoff(inputs={"topic": topic})
        self.state.research_brief = str(result)
        return result

    @listen(research_phase)
    def writing_phase(self, research_result):
        """Run the writing crew with research context."""
        writing_crew = Crew(
            agents=[writer, editor],
            tasks=[writing_task, editing_task],
            process=Process.sequential
        )

        result = writing_crew.kickoff(inputs={
            "topic": self.state.topic,
            "research": self.state.research_brief
        })
        self.state.draft_article = str(result)
        return result

    @router(writing_phase)
    def quality_check(self, draft):
        """Route based on quality assessment."""
        # Simulate quality scoring
        quality_score = assess_quality(draft)
        self.state.quality_score = quality_score
        self.state.iteration_count += 1

        if quality_score >= 0.8:
            return "publish"
        elif self.state.iteration_count < 3:
            return "revise"
        else:
            return "publish"  # Publish after 3 iterations

    @listen("publish")
    def publish_content(self):
        """Finalize and publish the content."""
        self.state.final_article = self.state.draft_article

        # Run social media crew
        social_crew = Crew(
            agents=[social_media_agent],
            tasks=[social_task],
            process=Process.sequential
        )

        social_result = social_crew.kickoff(inputs={
            "article": self.state.final_article
        })

        return {
            "article": self.state.final_article,
            "social_posts": str(social_result),
            "quality_score": self.state.quality_score
        }

    @listen("revise")
    def revise_content(self):
        """Send back for revision."""
        print(f"Quality score {self.state.quality_score} - revising...")
        # This will trigger writing_phase again
        return self.state.research_brief

# Run the flow
flow = ContentCreationFlow()
result = flow.kickoff(inputs={"topic": "AI Agent Best Practices 2025"})
```

class ParallelResearchFlow(Flow[ContentState]):
    """Flow that runs multiple research tracks in parallel."""

    @start()
    def initialize(self):
        return self.state.topic

    @listen(initialize)
    def technical_research(self, topic):
        """Research technical aspects."""
        # Returns technical findings
        return run_technical_crew(topic)

    @listen(initialize)
    def market_research(self, topic):
        """Research market aspects in parallel."""
        # Returns market findings
        return run_market_crew(topic)

    @listen(initialize)

### Memory Types Explained

| Memory Type    | Purpose                      | Persistence       | Use Case                         | Human Analogy                       |
| :------------- | :--------------------------- | :---------------- | :------------------------------- | :---------------------------------- |
| **Short-Term** | Current execution context    | Session only      | Sharing results between tasks    | Working memory during a meeting     |
| **Long-Term**  | Historical learnings         | Across executions | Improving over time              | Lessons learned from past projects  |
| **Entity**     | Key people, places, concepts | Across executions | Maintaining entity relationships | Your contact list and relationships |
| **Contextual** | Task-specific context        | Per task          | Understanding nuances            | Context-specific expertise          |

**Real-World Analogy**: Think of memory types like a professional's knowledge system:

- **Short-Term**: Notes you take during today's meetings (forgotten after the day)
- **Long-Term**: Your career experience and lessons learned over years
- **Entity**: Your professional network—who knows what, who works where
- **Contextual**: Domain-specific knowledge you activate for specific projects

## 37.8 Async Execution and Parallel Tasks

CrewAI supports asynchronous execution for running multiple crews or tasks concurrently, significantly reducing total execution time.

<Mermaid
  chart={`

    dateFormat s
    axisFormat %s
    
    section Sequential (180s)
    Task A :a1, 0, 60
    Task B :a2, 60, 60
    Task C :a3, 120, 60
    
    section Async (60s)
    Task A :b1, 0, 60
    Task B :b2, 0, 60

`}
  caption="Async Execution: 3x speedup for independent tasks."
/>

**Real-World Analogy**: Sequential execution is like doing laundry one load at a time—wash, dry, fold, repeat. Parallel execution is like running multiple washers and dryers simultaneously. If you have 3 loads and each takes 60 minutes sequentially (180 min total), running them in parallel takes just 60 minutes. Same concept applies to independent agent tasks.

### Async Crew Execution

```python
import asyncio
from crewai import Crew

async def run_multiple_crews():
    """Run multiple crews concurrently."""

    # Define different crews for different topics
    topics = [
        "AI Agent Frameworks",
        "Vector Databases",
        "LLM Fine-tuning"
    ]

    async def run_crew_for_topic(topic):
        crew = Crew(
            agents=[researcher, writer],
            tasks=[research_task, writing_task],
            process=Process.sequential
        )
        # Use kickoff_async for non-blocking execution
        result = await crew.kickoff_async(inputs={"topic": topic})
        return result

    # Run all crews concurrently
    results = await asyncio.gather(*[
        run_crew_for_topic(topic) for topic in topics
    ])

    return results

# Execute
results = asyncio.run(run_multiple_crews())
```

## 37.10 Production Considerations

### Error Handling and Retries

```python
from crewai import Crew
from tenacity import retry, stop_after_attempt, wait_exponential
import logging

logger = logging.getLogger(__name__)

@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=4, max=60)
)
def run_crew_with_retry(topic: str):
    """Run crew with automatic retry on failure."""
    try:
        result = content_crew.kickoff(inputs={"topic": topic})
        return result
    except Exception as e:
        logger.error(f"Crew failed: {e}")
        raise

# With timeout
import asyncio

async def run_crew_with_timeout(topic: str, timeout: int = 600):
    """Run crew with timeout protection."""
    try:
        result = await asyncio.wait_for(
            asyncio.to_thread(
                content_crew.kickoff,
                inputs={"topic": topic}
            ),
            timeout=timeout
        )
        return result
    except asyncio.TimeoutError:
        logger.error("Crew execution timed out")
        return None
```

### Production Monitoring

```python
import time
from dataclasses import dataclass
from typing import Optional

@dataclass
class ExecutionMetrics:
    crew_name: str
    start_time: float
    end_time: Optional[float] = None
    success: bool = False
    error: Optional[str] = None
    token_count: int = 0
    cost_usd: float = 0.0

class CrewMonitor:
    """Monitor crew executions for production observability."""

    def __init__(self):
        self.executions = []

    def track_execution(self, crew_name: str):
        """Context manager for tracking execution."""
        metrics = ExecutionMetrics(
            crew_name=crew_name,
            start_time=time.time()
        )

        class ExecutionTracker:
            def __enter__(tracker_self):
                return metrics

            def __exit__(tracker_self, exc_type, exc_val, exc_tb):
                metrics.end_time = time.time()
                metrics.success = exc_type is None
                if exc_val:
                    metrics.error = str(exc_val)
                self.executions.append(metrics)

        return ExecutionTracker()

    def get_stats(self):
        """Get aggregated statistics."""
        if not self.executions:
            return {}

        successful = [e for e in self.executions if e.success]
        durations = [
            e.end_time - e.start_time
            for e in self.executions
            if e.end_time
        ]

        return {
            "total_executions": len(self.executions),
            "success_rate": len(successful) / len(self.executions),
            "avg_duration": sum(durations) / len(durations) if durations else 0,
            "total_cost": sum(e.cost_usd for e in self.executions)
        }

# Usage
monitor = CrewMonitor()

with monitor.track_execution("content_crew") as metrics:
    result, cost_info = run_with_cost_tracking("AI Agents")
    metrics.token_count = cost_info["tokens"]
    metrics.cost_usd = cost_info["cost"]

print(monitor.get_stats())
```

### Comparison Matrix

| Feature               | CrewAI           | LangGraph       | AutoGen       | Swarm                |
| :-------------------- | :--------------- | :-------------- | :------------ | :------------------- |
| **Philosophy**        | Role-based teams | Stateful graphs | Conversations | Lightweight handoffs |

### When to Choose Each Framework

<Callout type="info">
  **CrewAI** excels when your problem naturally maps to a team of specialists
  (researcher, writer, editor). The role-based metaphor makes it intuitive to
  design and debug.
</Callout>

<Callout type="warning">
  **LangGraph** is ideal when you need fine-grained control over state
  transitions, explicit checkpointing, and complex conditional logic. The
  tradeoff is more boilerplate code.
</Callout>

<Callout type="tip">
  **AutoGen** shines for conversational multi-agent scenarios where agents need
  to discuss, debate, and iterate. It has excellent human-in-the-loop support.
</Callout>

<Callout type="note">
  **Swarm** (by OpenAI) is best for simple agent handoffs where you want minimal
  overhead. It's experimental but great for learning multi-agent concepts.
</Callout>

### Pattern 1: Task Context (CrewAI Default)

The most common pattern—tasks pass their outputs as context to dependent tasks:

```python
# Task B receives Task A's output automatically
task_a = Task(description="Research topic", agent=researcher)
task_b = Task(
    description="Write based on research",
    agent=writer,
    context=[task_a]  # Receives task_a output
)
```

### Pattern 2: Hierarchical Delegation

A manager agent delegates to specialists:

```python
crew = Crew(
    agents=[manager, researcher, writer, editor],
    tasks=[coordination_task],
    process=Process.hierarchical,
    manager_agent=manager  # Manager delegates dynamically
)
```

### Pattern 3: Shared Memory

Agents share information through memory systems:

```python
crew = Crew(
    agents=[agent_a, agent_b, agent_c],
    tasks=[task_a, task_b, task_c],
    memory=True,  # Enables shared memory
    embedder={"provider": "openai", "config": {"model": "text-embedding-3-small"}}
)
```

### Pattern 4: Callback Communication

Use callbacks for real-time communication:

```python
def on_task_complete(task_output):
    """Called when any task completes."""
    # Notify other systems, update dashboards, etc.
    send_notification(f"Task completed: {task_output.description}")

crew = Crew(
    agents=[researcher, writer],
    tasks=[research_task, writing_task],
    task_callback=on_task_complete
)
```
