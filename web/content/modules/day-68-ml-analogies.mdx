### Practical Application: Structured Feature Extraction

When designing agent prompts, think about what "features" you want the agent to extract. The key insight from 2024-2025 research is that **structured outputs** dramatically improve feature extraction quality:

```python
# Bad: Vague prompt (poor feature specification)
prompt = "Review this code"

# Good: Explicit feature guidance with structured output
prompt = """
Analyze this code and extract the following features:

## Security Analysis
- Vulnerability type (SQL injection, XSS, auth bypass, none)
- Severity score (1-5)
- Affected lines
- Remediation steps

## Performance Analysis
- Bottleneck type (N+1 queries, memory leaks, blocking I/O, none)
- Impact score (1-5)
- Optimization suggestions

## Maintainability Analysis
- Code smell patterns detected
- Coupling score (1-5)
- Suggested refactoring

Return as structured JSON matching the FeatureReport schema.
"""

# Even better: Use tool calling for guaranteed structure
class SecurityFeature(BaseModel):
    vulnerability_type: Literal["sql_injection", "xss", "auth_bypass", "none"]
    severity: int = Field(ge=1, le=5)
    affected_lines: list[int]
    remediation: str

# The agent's kernel now has explicit feature dimensions
```

### The Semantic Kernel Analogy

Just as different kernels (linear, polynomial, RBF) are suited for different data distributions, different prompting strategies act as "semantic kernels" for different problem types:

| ML Kernel      | Agentic Equivalent      | Best For                         |
| -------------- | ----------------------- | -------------------------------- |
| Linear         | Direct instruction      | Simple, well-defined tasks       |
| Polynomial     | Chain-of-thought        | Multi-step reasoning             |
| RBF (Gaussian) | Few-shot examples       | Pattern matching, style transfer |
| Custom         | Domain-specific prompts | Specialized domains              |

### Mixture of Experts (MoE): Dynamic Agent Routing

<Callout type="info">
  **2025 Insight:** Mixture of Experts architectures have become the dominant
  paradigm for scaling LLMs efficiently. Models like GPT-4, Gemini, and Llama 4
  use MoE internally. This same pattern applies directly to multi-agent systems.
</Callout>

The key difference between traditional ensembles and MoE is **dynamic routing**—not all experts process every input. A router decides which specialists to activate based on the input characteristics:

```python
from enum import Enum
from pydantic import BaseModel

class ExpertType(str, Enum):
    SECURITY = "security"
    PERFORMANCE = "performance"
    ARCHITECTURE = "architecture"
    DATA = "data"

class RoutingDecision(BaseModel):
    """MoE-style routing: select top-k experts per input."""
    selected_experts: list[ExpertType]
    confidence_scores: dict[ExpertType, float]
    reasoning: str

class MoEOrchestrator:
    """Mixture of Experts pattern for agent routing."""

    def __init__(self, experts: dict[ExpertType, Agent]):
        self.experts = experts
        self.router = self._create_router()

    def _create_router(self) -> Agent:
        """Router agent decides which experts to activate."""
        return Agent(
            system_prompt="""You are an expert router. Analyze the input and decide
            which specialist agents should handle it. Select 1-3 experts based on
            the problem characteristics. Not every expert needs to be consulted.""",
            output_schema=RoutingDecision
        )

    async def process(self, input: str, top_k: int = 2) -> dict:
        # Step 1: Route to appropriate experts (sparse activation)
        routing = await self.router.invoke(input)
        selected = routing.selected_experts[:top_k]

        # Step 2: Only activate selected experts (efficiency gain)
        results = await asyncio.gather(*[
            self.experts[expert].invoke(input)
            for expert in selected
        ])

        # Step 3: Weighted aggregation based on confidence
        return self._aggregate_with_weights(
            results,
            {e: routing.confidence_scores[e] for e in selected}
        )
```

### Chain-of-Thought as Computational Depth

<Callout type="tip">
  **2025 Breakthrough:** OpenAI's o1/o3 series and similar reasoning models have
  proven that "thinking tokens" dramatically improve performance on complex
  tasks. This is the neural network depth analogy made explicit—more hidden
  layers (reasoning steps) enable more complex computations.
</Callout>

The reasoning revolution of 2024-2025 showed that LLMs can be trained to generate internal reasoning traces before producing outputs. This is analogous to adding more hidden layers to a neural network:

```python
class ReasoningDepthController:
    """Control computational depth based on task complexity."""

    DEPTH_CONFIGS = {
        "shallow": {  # Simple tasks: 1-2 reasoning steps
            "max_thinking_tokens": 500,
            "model": "claude-3-haiku",
            "prompt_style": "direct"
        },
        "medium": {  # Moderate tasks: 3-5 reasoning steps
            "max_thinking_tokens": 2000,
            "model": "claude-3-sonnet",
            "prompt_style": "chain_of_thought"
        },
        "deep": {  # Complex tasks: 10+ reasoning steps
            "max_thinking_tokens": 10000,
            "model": "claude-3-opus",
            "prompt_style": "extended_thinking"
        }
    }

    async def process_with_adaptive_depth(
        self,
        task: str,
        complexity_estimate: str
    ) -> dict:
        """Like choosing network depth based on task complexity."""
        config = self.DEPTH_CONFIGS[complexity_estimate]

        if config["prompt_style"] == "extended_thinking":
            # Deep reasoning: many hidden computational steps
            return await self._deep_reasoning(task, config)
        elif config["prompt_style"] == "chain_of_thought":
            # Medium depth: explicit reasoning chain
            return await self._cot_reasoning(task, config)
        else:
            # Shallow: direct response
            return await self._direct_response(task, config)

    async def _deep_reasoning(self, task: str, config: dict) -> dict:
        """Extended thinking with hidden reasoning tokens."""
        response = await client.messages.create(
            model=config["model"],
            max_tokens=16000,
            thinking={
                "type": "enabled",
                "budget_tokens": config["max_thinking_tokens"]
            },
            messages=[{"role": "user", "content": task}]
        )

        # The thinking tokens are "hidden layers" -
        # we don't need to interpret them, just trust the output
        return {
            "output": response.content[-1].text,
            "thinking_tokens_used": response.usage.thinking_tokens,
            "computational_depth": "deep"
        }
```

class ResearchState(TypedDict):

        f"Generate 5 research hypotheses for: {state['query']}"

def query_expander(state: ResearchState) -> dict:

### Context Compression Strategies

![Context Compression Prism](/images/context_prism.png)

<Callout type="info">
  **2025 Reality:** Context windows have expanded dramatically (GPT-4 Turbo:
  128K, Gemini 1.5 Pro: 2M+, Claude: 200K), but research shows that "lost in the
  middle" effects persist. More context doesn't mean better results—strategic
  compression remains essential.
</Callout>

```python
class ContextCompressor:
    """Apply PCA-like thinking to agent context."""

    def compress_logs(self, logs: list[str], max_tokens: int = 2000) -> str:
        """Reduce log dimensionality while preserving signal."""
        # Strategy 1: Error-focused (high variance events)
        errors = [l for l in logs if "ERROR" in l or "CRITICAL" in l]

        # Strategy 2: Temporal sampling (recent = higher weight)
        recent = logs[-100:]

        # Strategy 3: Deduplication (remove redundant dimensions)
        unique_patterns = self.deduplicate_similar(logs)

        # Combine like PCA components
        compressed = self.synthesize([errors, recent, unique_patterns])
        return self.truncate_to_tokens(compressed, max_tokens)

    def compress_codebase(self, files: list[str], query: str) -> str:
        """Extract relevant code dimensions for a query."""
        # Like choosing which principal components to keep
        # based on the downstream task
        relevant_files = self.semantic_search(files, query, top_k=10)
        summaries = [self.summarize_file(f) for f in relevant_files]
        return "\n".join(summaries)
```

### Hierarchical Context Compression

Modern agents use multi-level compression, analogous to hierarchical feature learning in deep networks:

```python
class HierarchicalContextManager:
    """Multi-level context compression like CNN feature hierarchies."""

    def __init__(self):
        self.levels = {
            "raw": [],        # Full detail (like pixel values)
            "summary": [],    # Compressed summaries (like edge features)
            "semantic": [],   # High-level concepts (like object features)
            "episodic": []    # Key events only (like scene understanding)
        }

    def add_interaction(self, interaction: dict):
        """Compress interaction through hierarchy."""
        # Level 0: Store raw (limited window)
        self.levels["raw"].append(interaction)
        if len(self.levels["raw"]) > 10:
            # Compress oldest to summary level
            oldest = self.levels["raw"].pop(0)
            self.levels["summary"].append(self._summarize(oldest))

        # Level 1 -> Level 2: Periodic semantic compression
        if len(self.levels["summary"]) > 20:
            batch = self.levels["summary"][:10]
            self.levels["summary"] = self.levels["summary"][10:]
            self.levels["semantic"].append(self._extract_themes(batch))

        # Level 2 -> Level 3: Extract only key episodes
        if len(self.levels["semantic"]) > 10:
            key_events = self._identify_key_events(self.levels["semantic"])
            self.levels["episodic"].extend(key_events)
            self.levels["semantic"] = []

    def get_context(self, query: str, max_tokens: int = 4000) -> str:
        """Retrieve context with task-relevant compression."""
        # Like attention over different feature levels
        context_parts = []

        # Always include recent raw interactions
        context_parts.append(("raw", self.levels["raw"][-5:]))

        # Include relevant summaries
        relevant_summaries = self._search_relevant(
            self.levels["summary"], query, top_k=5
        )
        context_parts.append(("summary", relevant_summaries))

        # Include relevant semantic themes
        relevant_themes = self._search_relevant(
            self.levels["semantic"], query, top_k=3
        )
        context_parts.append(("semantic", relevant_themes))

        # Always include key episodes
        context_parts.append(("episodic", self.levels["episodic"]))

        return self._format_hierarchical_context(context_parts, max_tokens)
```

### The Exploration-Exploitation Tradeoff

<Mermaid
  chart={`
graph LR

    B -->|Explore| C[Try New Approach]
    B -->|Exploit| D[Use Known Solution]

```python
class ExplorationController:
    """Control exploration vs exploitation in agent behavior."""

    def __init__(self, epsilon: float = 0.1):
        self.epsilon = epsilon  # Exploration rate
        self.action_values = {}  # Q-values for actions
        self.action_counts = {}  # Visit counts

    def select_approach(
        self,
        task: str,
        available_approaches: list[str]
    ) -> str:
        """Epsilon-greedy approach selection."""
        import random

        if random.random() < self.epsilon:
            # Explore: try a random approach
            return random.choice(available_approaches)
        else:
            # Exploit: use best known approach
            return self._get_best_approach(task, available_approaches)

    def _get_best_approach(
        self,
        task: str,
        approaches: list[str]
    ) -> str:
        """Select approach with highest estimated value."""
        task_type = self._classify_task(task)

        best_approach = None
        best_value = float('-inf')

        for approach in approaches:
            key = (task_type, approach)
            value = self.action_values.get(key, 0.0)

            # UCB bonus for under-explored approaches
            count = self.action_counts.get(key, 0)
            ucb_bonus = math.sqrt(2 * math.log(sum(self.action_counts.values()) + 1) / (count + 1))

            if value + ucb_bonus > best_value:
                best_value = value + ucb_bonus
                best_approach = approach

        return best_approach or approaches[0]

    def update_from_feedback(
        self,
        task: str,
        approach: str,
        reward: float
    ):
        """Update action values based on outcome (like Q-learning)."""
        task_type = self._classify_task(task)
        key = (task_type, approach)

        # Incremental mean update
        count = self.action_counts.get(key, 0)
        old_value = self.action_values.get(key, 0.0)

        self.action_counts[key] = count + 1
        self.action_values[key] = old_value + (reward - old_value) / (count + 1)
```

### Reward Shaping for Agents

Just as reward shaping is critical in RL, designing good feedback signals is essential for agent systems:

```python
class AgentRewardSystem:
    """Multi-objective reward system for agent optimization."""

    def calculate_reward(self, result: AgentResult) -> float:
        """Composite reward function with multiple objectives."""
        rewards = {
            # Primary objective: task success
            "task_success": self._task_success_reward(result),

            # Secondary: efficiency
            "efficiency": self._efficiency_reward(result),

            # Tertiary: safety/reliability
            "safety": self._safety_reward(result),

            # Quaternary: user satisfaction
            "user_satisfaction": self._user_satisfaction_reward(result)
        }

        # Weighted combination (like multi-objective RL)
        weights = {
            "task_success": 0.5,
            "efficiency": 0.2,
            "safety": 0.2,
            "user_satisfaction": 0.1
        }

        return sum(rewards[k] * weights[k] for k in rewards)

    def _task_success_reward(self, result: AgentResult) -> float:
        """Did the agent accomplish the goal?"""
        if result.goal_achieved:
            return 1.0
        elif result.partial_progress:
            return 0.5
        else:
            return 0.0

    def _efficiency_reward(self, result: AgentResult) -> float:
        """Reward for using fewer resources."""
        # Penalize excessive token usage, API calls, time
        token_penalty = min(result.tokens_used / 10000, 1.0)
        time_penalty = min(result.execution_time / 60, 1.0)
        return 1.0 - (0.5 * token_penalty + 0.5 * time_penalty)

    def _safety_reward(self, result: AgentResult) -> float:
        """Reward for safe, reliable behavior."""
        penalties = 0.0
        if result.had_errors:
            penalties += 0.3
        if result.required_human_intervention:
            penalties += 0.2
        if result.made_irreversible_actions:
            penalties += 0.5
        return max(0.0, 1.0 - penalties)
```

### The "Lost in the Middle" Problem

<Callout type="warning">
  **Critical 2025 Finding:** Research has consistently shown that LLMs struggle
  with information in the middle of long contexts. Information at the beginning
  and end receives more "attention" than middle content. This has direct
  implications for agent design.
</Callout>

```python
class AttentionAwareContextBuilder:
    """Build context with attention patterns in mind."""

    def build_context(
        self,
        task: str,
        information: list[dict],
        max_tokens: int = 8000
    ) -> str:
        """Structure context to maximize attention on important info."""

        # Score information by relevance to task
        scored = [(info, self._relevance_score(info, task)) for info in information]
        scored.sort(key=lambda x: x[1], reverse=True)

        # Apply attention-aware positioning
        # Most important: beginning and end (high attention)
        # Less important: middle (lower attention)

        high_priority = [s[0] for s in scored[:3]]  # Top 3
        medium_priority = [s[0] for s in scored[3:7]]  # Next 4
        low_priority = [s[0] for s in scored[7:]]  # Rest

        context_parts = []

        # BEGINNING: Highest priority items (primacy effect)
        context_parts.append("## Critical Information")
        for info in high_priority:
            context_parts.append(self._format_info(info))

        # MIDDLE: Lower priority items (attention valley)
        if low_priority:
            context_parts.append("\n## Additional Context")
            for info in low_priority:
                context_parts.append(self._format_info(info, condensed=True))

        # END: Medium priority items (recency effect)
        context_parts.append("\n## Key Details to Remember")
        for info in medium_priority:
            context_parts.append(self._format_info(info))

        # Final reminder of task (recency boost)
        context_parts.append(f"\n## Your Task\n{task}")

        return "\n".join(context_parts)
```

### Multi-Head Attention for Agents

Just as transformers use multiple attention heads to capture different types of relationships, agents can use multiple "attention strategies" simultaneously:

```python
class MultiHeadAgentAttention:
    """Multiple attention strategies for comprehensive focus."""

    def __init__(self):
        self.attention_heads = {
            "semantic": self._semantic_attention,    # Meaning-based
            "structural": self._structural_attention, # Code/doc structure
            "temporal": self._temporal_attention,     # Time-based relevance
            "causal": self._causal_attention,         # Cause-effect chains
        }

    async def attend(
        self,
        query: str,
        documents: list[str],
        head_weights: dict[str, float] = None
    ) -> list[tuple[str, float]]:
        """Multi-head attention over documents."""

        head_weights = head_weights or {
            "semantic": 0.4,
            "structural": 0.2,
            "temporal": 0.2,
            "causal": 0.2
        }

        # Compute attention scores from each head
        all_scores = {}
        for head_name, head_fn in self.attention_heads.items():
            scores = await head_fn(query, documents)
            weight = head_weights.get(head_name, 0.25)

            for doc, score in scores:
                if doc not in all_scores:
                    all_scores[doc] = 0.0
                all_scores[doc] += score * weight

        # Return documents sorted by combined attention score
        return sorted(all_scores.items(), key=lambda x: x[1], reverse=True)

    async def _semantic_attention(
        self,
        query: str,
        documents: list[str]
    ) -> list[tuple[str, float]]:
        """Attention based on semantic similarity."""
        query_embedding = await self.embed(query)
        doc_embeddings = await asyncio.gather(*[
            self.embed(doc) for doc in documents
        ])

        scores = [
            (doc, cosine_similarity(query_embedding, emb))
            for doc, emb in zip(documents, doc_embeddings)
        ]
        return scores

    async def _temporal_attention(
        self,
        query: str,
        documents: list[str]
    ) -> list[tuple[str, float]]:
        """Attention weighted by recency."""
        scores = []
        for i, doc in enumerate(documents):
            # More recent = higher score (assuming chronological order)
            recency_score = (i + 1) / len(documents)
            scores.append((doc, recency_score))
        return scores
```

### The Transfer Learning Spectrum for Agents

```python
from enum import Enum

class AdaptationStrategy(Enum):
    """Strategies ordered by adaptation depth."""
    PROMPT_ENGINEERING = "prompt"      # Lightest: guide existing knowledge
    FEW_SHOT_EXAMPLES = "few_shot"     # Light: show examples in context
    RAG_AUGMENTATION = "rag"           # Medium: add external knowledge
    FINE_TUNING = "fine_tune"          # Heavy: modify model weights
    CONTINUED_PRETRAINING = "pretrain" # Heaviest: extensive retraining

class TransferLearningAdvisor:
    """Recommend adaptation strategy based on domain gap."""

    def recommend_strategy(
        self,
        domain_gap: str,  # "small", "medium", "large"
        data_availability: str,  # "none", "few", "moderate", "abundant"
        latency_requirements: str,  # "real_time", "batch"
        budget: str  # "low", "medium", "high"
    ) -> AdaptationStrategy:
        """Recommend transfer learning strategy."""

        # Small domain gap: prompt engineering usually sufficient
        if domain_gap == "small":
            if data_availability in ["few", "moderate"]:
                return AdaptationStrategy.FEW_SHOT_EXAMPLES
            return AdaptationStrategy.PROMPT_ENGINEERING

        # Medium domain gap: RAG or few-shot
        if domain_gap == "medium":
            if data_availability == "abundant" and budget == "high":
                return AdaptationStrategy.FINE_TUNING
            if data_availability in ["moderate", "abundant"]:
                return AdaptationStrategy.RAG_AUGMENTATION
            return AdaptationStrategy.FEW_SHOT_EXAMPLES

        # Large domain gap: fine-tuning or continued pretraining
        if domain_gap == "large":
            if data_availability == "abundant" and budget == "high":
                return AdaptationStrategy.CONTINUED_PRETRAINING
            if data_availability in ["moderate", "abundant"]:
                return AdaptationStrategy.FINE_TUNING
            # Fallback: RAG can help even with large gaps
            return AdaptationStrategy.RAG_AUGMENTATION
```

### Practical Transfer Learning Patterns

```python
class DomainAdaptedAgent:
    """Agent with layered transfer learning."""

    def __init__(
        self,
        base_model: str,
        domain: str,
        adaptation_config: dict
    ):
        self.base_model = base_model
        self.domain = domain

        # Layer 1: Domain-specific system prompt (always applied)
        self.system_prompt = self._load_domain_prompt(domain)

        # Layer 2: Few-shot examples (if available)
        self.few_shot_examples = self._load_examples(domain)

        # Layer 3: RAG knowledge base (if configured)
        self.knowledge_base = self._init_knowledge_base(
            adaptation_config.get("knowledge_sources", [])
        )

        # Layer 4: Fine-tuned model (if available)
        self.fine_tuned_model = adaptation_config.get("fine_tuned_model")

    async def invoke(self, query: str) -> str:
        """Invoke with all transfer learning layers."""

        # Select model (fine-tuned if available)
        model = self.fine_tuned_model or self.base_model

        # Build context with transfer learning layers
        messages = [{"role": "system", "content": self.system_prompt}]

        # Add few-shot examples
        for example in self.few_shot_examples[:3]:
            messages.append({"role": "user", "content": example["input"]})
            messages.append({"role": "assistant", "content": example["output"]})

        # Add RAG context
        if self.knowledge_base:
            relevant_docs = await self.knowledge_base.search(query, top_k=5)
            rag_context = self._format_rag_context(relevant_docs)
            messages.append({
                "role": "user",
                "content": f"Relevant context:\n{rag_context}\n\nQuery: {query}"
            })
        else:
            messages.append({"role": "user", "content": query})

        return await self._call_model(model, messages)

    def _load_domain_prompt(self, domain: str) -> str:
        """Load domain-specific system prompt."""
        prompts = {
            "legal": """You are a legal analysis assistant. You understand
                legal terminology, case law citation formats, and regulatory
                frameworks. Always cite sources and note jurisdictional limits.""",
            "medical": """You are a medical information assistant. You understand
                clinical terminology, drug interactions, and diagnostic criteria.
                Always recommend consulting healthcare professionals for decisions.""",
            "codebase": """You are a codebase expert for this specific repository.
                You understand the architecture, conventions, and patterns used here.
                Reference specific files and functions when relevant."""
        }
        return prompts.get(domain, "You are a helpful assistant.")
```

### Agent Hallucination as Overfitting

<Callout type="warning">
  **Key Insight:** Hallucination is fundamentally an overfitting problem. The
  model has learned to generate plausible-sounding text so well that it
  generates plausible-sounding text even when it doesn't have the knowledge to

```python
class RegularizedAgent:
    """Agent with multiple regularization techniques."""

    def __init__(self, base_agent: Agent):
        self.base_agent = base_agent
        self.regularizers = [
            RAGGrounding(),           # L2-like: pull toward known facts
            ConfidenceCalibration(),  # Dropout-like: express uncertainty
            OutputConstraints(),      # L1-like: sparse, structured outputs
            MultiAgentVerification(), # Ensemble regularization
        ]

    async def invoke(self, query: str) -> RegularizedResponse:
        """Invoke with all regularization layers."""

        # Get base response
        base_response = await self.base_agent.invoke(query)

        # Apply regularization pipeline
        regularized = base_response
        for regularizer in self.regularizers:
            regularized = await regularizer.apply(regularized, query)

        return regularized

class RAGGrounding:
    """Regularization via retrieval-augmented generation."""

    async def apply(
        self,
        response: str,
        query: str
    ) -> RegularizedResponse:
        """Ground response in retrieved facts (like L2 regularization)."""

        # Retrieve relevant facts
        facts = await self.knowledge_base.search(query, top_k=5)

        # Check response against facts
        grounding_check = await self.verify_against_facts(response, facts)

        if grounding_check.confidence < 0.7:
            # Re-generate with explicit grounding
            grounded_response = await self.regenerate_with_facts(
                query, response, facts
            )
            return RegularizedResponse(
                content=grounded_response,
                grounding_score=grounding_check.confidence,
                sources=facts,
                was_regularized=True
            )

        return RegularizedResponse(
            content=response,
            grounding_score=grounding_check.confidence,
            sources=facts,
            was_regularized=False
        )

class ConfidenceCalibration:
    """Regularization via uncertainty quantification."""

    async def apply(
        self,
        response: RegularizedResponse,
        query: str
    ) -> RegularizedResponse:
        """Add calibrated confidence scores (like dropout)."""

        # Generate multiple responses (like MC dropout)
        variations = await self.generate_variations(query, n=3)

        # Measure consistency
        consistency_score = self.measure_consistency(
            response.content, variations
        )

        # Calibrate confidence based on consistency
        if consistency_score < 0.6:
            response.confidence = "low"
            response.content = self._add_uncertainty_markers(response.content)
        elif consistency_score < 0.85:
            response.confidence = "medium"
        else:
            response.confidence = "high"

        return response

    def _add_uncertainty_markers(self, content: str) -> str:
        """Add explicit uncertainty language."""
        return f"""Note: I have moderate uncertainty about this response.

{content}

Please verify this information from authoritative sources before relying on it."""

class OutputConstraints:
    """L1-like regularization via structured outputs."""

    def __init__(self, schema: type[BaseModel]):
        self.schema = schema

    async def apply(
        self,
        response: RegularizedResponse,
        query: str
    ) -> RegularizedResponse:

        # Parse into structured format
        try:
            structured = await self.parse_to_schema(response.content)
            response.structured_output = structured
            response.schema_valid = True
        except ValidationError as e:
            # Regenerate with explicit schema guidance

class MultiAgentVerification:
    """Ensemble regularization via cross-verification."""

    def __init__(self, verifier_agents: list[Agent]):
        self.verifiers = verifier_agents

    async def apply(
        self,
        response: RegularizedResponse,
        query: str
    ) -> RegularizedResponse:
        """Cross-verify with multiple agents."""

        verification_prompt = f"""
        Original query: {query}
        Proposed response: {response.content}

        Verify this response for:
        1. Factual accuracy
        2. Logical consistency
        3. Completeness

        Return: VERIFIED, NEEDS_REVISION, or INCORRECT with explanation.
        """

        verifications = await asyncio.gather(*[
            agent.invoke(verification_prompt)
            for agent in self.verifiers
        ])

        # Majority voting
        verified_count = sum(
            1 for v in verifications if "VERIFIED" in v
        )

        if verified_count < len(self.verifiers) / 2:
            # Consensus says revision needed
            response.verification_status = "needs_revision"
            response.verification_notes = verifications
        else:
            response.verification_status = "verified"

        return response
```

```python
class AgentOptimizer:
    """Gradient descent-style optimization for agent configurations."""

    def __init__(
        self,
        agent_factory: Callable[[AgentConfig], Agent],
        eval_dataset: list[EvalExample],
        loss_fn: Callable[[str, str], float]
    ):
        self.agent_factory = agent_factory
        self.eval_dataset = eval_dataset
        self.loss_fn = loss_fn

        # Optimization hyperparameters
        self.learning_rate = 0.1
        self.momentum = 0.9
        self.velocity = {}  # For momentum

    async def optimize(
        self,
        initial_config: AgentConfig,
        max_iterations: int = 10
    ) -> AgentConfig:
        """Optimize agent configuration via gradient descent."""

        config = initial_config
        best_config = config
        best_loss = float('inf')

        for iteration in range(max_iterations):
            # Forward pass: evaluate current config
            agent = self.agent_factory(config)
            loss, metrics = await self._evaluate(agent)

            print(f"Iteration {iteration}: loss={loss:.4f}")

            if loss < best_loss:
                best_loss = loss
                best_config = config.copy()

            # Compute gradients (what to change)
            gradients = await self._compute_gradients(config, metrics)

            # Update with momentum
            config = self._apply_gradients(config, gradients)

        return best_config

    async def _evaluate(self, agent: Agent) -> tuple[float, dict]:
        """Evaluate agent on dataset (forward pass)."""
        total_loss = 0.0
        metrics = {"correct": 0, "total": 0, "errors": []}

        for example in self.eval_dataset:
            response = await agent.invoke(example.input)
            loss = self.loss_fn(response, example.expected_output)
            total_loss += loss

            metrics["total"] += 1
            if loss < 0.1:  # Threshold for "correct"
                metrics["correct"] += 1
            else:
                metrics["errors"].append({
                    "input": example.input,
                    "expected": example.expected_output,
                    "actual": response,
                    "loss": loss
                })

        return total_loss / len(self.eval_dataset), metrics

    async def _compute_gradients(
        self,
        config: AgentConfig,
        metrics: dict
    ) -> dict:
        """Compute 'gradients' - what changes would improve performance."""

        # Analyze errors to determine gradient direction
        error_analysis = await self._analyze_errors(metrics["errors"])

        gradients = {}

        # Gradient for system prompt
        if error_analysis.get("needs_clearer_instructions"):
            gradients["system_prompt"] = error_analysis["prompt_suggestions"]

        # Gradient for temperature
        if error_analysis.get("too_creative"):
            gradients["temperature"] = -0.1  # Decrease
        elif error_analysis.get("too_rigid"):
            gradients["temperature"] = 0.1   # Increase

        # Gradient for few-shot examples
        if error_analysis.get("missing_patterns"):
            gradients["few_shot_examples"] = error_analysis["suggested_examples"]

        return gradients

    def _apply_gradients(
        self,
        config: AgentConfig,
        gradients: dict
    ) -> AgentConfig:
        """Apply gradients with momentum."""
        new_config = config.copy()

        for param, gradient in gradients.items():
            # Update velocity (momentum)
            if param not in self.velocity:
                self.velocity[param] = gradient
            else:
                self.velocity[param] = (
                    self.momentum * self.velocity[param] +
                    (1 - self.momentum) * gradient
                )

            # Apply update
            if param == "temperature":
                new_config.temperature = max(0.0, min(1.0,
                    config.temperature + self.learning_rate * self.velocity[param]
                ))
            elif param == "system_prompt":
                new_config.system_prompt = self._merge_prompt_suggestions(
                    config.system_prompt, self.velocity[param]
                )
            elif param == "few_shot_examples":
                new_config.few_shot_examples = self._update_examples(
                    config.few_shot_examples, self.velocity[param]
                )

        return new_config
```

| ML Concept          | Agent Equivalent            | Practical Meaning                 |
| ------------------- | --------------------------- | --------------------------------- |
| High learning rate  | Large prompt changes        | Fast but unstable improvement     |
| Low learning rate   | Small prompt tweaks         | Slow but stable improvement       |
| Learning rate decay | Decreasing change magnitude | Converge to stable config         |
| Adaptive LR (Adam)  | Context-aware updates       | Different params, different rates |
| Warm restarts       | Periodic major revisions    | Escape local optima               |

<Callout type="tip">
  **Practical Tip:** Start with larger changes (high learning rate) to find a
  good region, then make smaller refinements (low learning rate) to converge.
  This mirrors learning rate schedules in deep learning.
</Callout>

```python
class IncidentAnalysisAgent:
    """Production incident analyzer using all ML analogies."""

    def __init__(self):
        # Ensemble/MoE: Specialist agents with routing
        self.router = MoEOrchestrator({
            "logs": LogAnalysisAgent(),
            "metrics": MetricsAnalysisAgent(),
            "code": CodeChangeAgent(),
            "alerts": AlertCorrelationAgent()
        })

        # Context compression (PCA)
        self.context_manager = HierarchicalContextManager()

        # Attention mechanism
        self.attention = MultiHeadAgentAttention()

        # Regularization layers
        self.regularizers = [
            RAGGrounding(knowledge_base=self.runbook_db),
            ConfidenceCalibration(),
            MultiAgentVerification([self.senior_sre_agent])
        ]

        # RL-style learning
        self.optimizer = ExplorationController(epsilon=0.1)

        # Transfer learning: domain adaptation
        self.domain_adapter = DomainAdaptedAgent(
            base_model="claude-3-opus",
            domain="infrastructure",
            adaptation_config={
                "knowledge_sources": ["runbooks", "past_incidents"],
                "few_shot_examples": self.load_past_resolutions()
            }
        )

    async def analyze_incident(self, incident: Incident) -> Analysis:
        """Full analysis pipeline with ML-informed design."""

        # Step 1: Compress context (PCA)
        compressed_logs = self.context_manager.compress_logs(
            incident.logs, max_tokens=4000
        )

        # Step 2: Attention-aware context building
        relevant_context = await self.attention.attend(
            query=incident.description,
            documents=[compressed_logs, incident.metrics, incident.alerts]
        )

        # Step 3: Route to specialists (MoE)
        specialist_findings = await self.router.process(
            incident.description, top_k=2
        )

        # Step 4: Deep reasoning (hidden layers)
        hypothesis = await self.domain_adapter.invoke(
            f"""Analyze this incident:
            {incident.description}

            Specialist findings: {specialist_findings}
            Context: {relevant_context}

            Generate root cause hypotheses."""
        )

        # Step 5: Regularization (prevent hallucination)
        for regularizer in self.regularizers:
            hypothesis = await regularizer.apply(hypothesis, incident.description)

        # Step 6: Update learning (RL)
        # This happens after human feedback on the analysis

        return Analysis(
            root_cause=hypothesis.content,
            confidence=hypothesis.confidence,
            sources=hypothesis.sources,
            specialist_contributions=specialist_findings
        )
```
