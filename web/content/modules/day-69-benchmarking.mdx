## 69.1 The "Vibe Check" Problem

{/* IMAGE_PLACEHOLDER: Create an illustration showing a developer confidently shipping code after testing with only 3 queries, followed by a flood of user complaints. Split-screen design: left side shows developer with 3 green checkmarks, right side shows multiple red X marks from production users. You build an agent. It works on your test query. You ship it.
A week later, users complain it's broken. What happened?

**The "Vibe Check" Trap:**

1.  Developer tries 3 queries.
2.  Agent gets 3/3 right.
3.  "It works!" -> Ship it.
4.  Reality: 3 samples is statistically insignificant.

<Callout type="warning">
  **The Law of Large Numbers:** You need at least 50-100 examples to have *any*
  confidence in an LLM system's performance. Stochasticity means "it worked
  once" proves nothing.
</Callout>

### 1. Deterministic Evals (Code/Math)

- **Binary**: Pass/Fail.
- **Tools**: `pytest`, `grep`, `jsonschema`.
- **Cost**: Cheap & Fast.
- **Use Case**: Coding agents, Structured Output.

### 2. LLM-as-a-Judge (Chat/Creative)

- **Scale**: 1-5 or boolean.
- **Tools**: GPT-4 evaluating Llama-3 output.
- **Cost**: Expensive & Slow.
- **Use Case**: Chatbots, Summarization.

### 3. Agentic Evaluation (2025)

Beyond just evaluating outputs, modern agent evaluation examines the entire trajectory:

- **Trajectory Evaluation**: Was the reasoning path efficient? Did the agent explore appropriately?
- **Tool Use Accuracy**: Did the agent call the right tools with correct parameters?
- **Multi-Turn Coherence**: Does the agent maintain context across conversation turns?
- **Cost-Adjusted Performance**: What's the accuracy per dollar spent?

## 69.5 Implementing Pass@k

{/* IMAGE_PLACEHOLDER: Create an interactive visualization showing Pass@k concept. Show 10 agent runs as circles, with some colored green (correct) and some red (incorrect). Demonstrate how Pass@1, Pass@5, and Pass@10 are calculated from the same set of runs. Include a formula visualization and example calculation. Style: educational diagram with clear visual distinction between success/failure, animated or interactive feel, modern color scheme. */}

Because agents are non-deterministic, a single run is noise. `Pass@k` measures: "If I run the agent `k` times, what's the probability at least one solution is correct?"

**Formula:** `Pass@k = 1 - C(n-c, k) / C(n, k)`

Where:

- `n`: total samples generated (e.g., 100)
- `c`: number of correct samples
- `k`: attempts allowed (e.g., 1, 5, 10)

### Why It Matters

{/* IMAGE_PLACEHOLDER: Create a comparison chart showing Pass@1 vs Pass@10 for different agent quality levels. Two side-by-side scenarios: "Reliable Agent" (high Pass@1, high Pass@10) vs "Inconsistent Agent" (low Pass@1, high Pass@10). Use visual metaphors like target accuracy or consistency meters. Include a callout highlighting why Pass@1 matters for production. Style: clean comparison layout, use icons and visual metaphors, professional color coding. */}

- **Pass@1**: Measures reliability (first-try success rate).
- **Pass@10**: Measures potential (best of 10 attempts).

<Callout type="tip">
  **Practical Tip**: For production systems, optimize for Pass@1. High Pass@10
  but low Pass@1 means your agent is inconsistent—users won't retry 10 times.
</Callout>

    }
    # ... add 50 more
]

# 2. The Agent
def run_agent(question):
    # ... your agent logic ...
    return executed_sql_result

# 3. The Evaluator
def evaluate(dataset):
    correct = 0
    total = len(dataset)

    results = []

    for item in tqdm(dataset):
        try:
            prediction = run_agent(item["question"])

            # Exact match check
            is_correct = (str(prediction) == str(item["answer_ground_truth"]))

            if is_correct:
                correct += 1

            results.append({
                "question": item["question"],
                "prediction": prediction,
                "ground_truth": item["answer_ground_truth"],
                "correct": is_correct
            })

        except Exception as e:
            results.append({"error": str(e), "correct": False})

    accuracy = correct / total
    print(f"Accuracy: {accuracy:.2%}")
    return results

# Run
evaluate(dataset)

## 📚 Key Takeaways

1.  **Vibe checks are dangerous**: Always use datasets > 50 examples.
2.  **SWE-bench is the gold standard**: Top agents now achieve 77%+ on Verified (2025).
3.  **New benchmarks for new capabilities**: ARC-AGI-2 for reasoning, τ-bench for tool use, WebArena for web agents.

**1. Shadow Mode Evaluation**
Run new agent versions alongside production without affecting users:

```python
async def shadow_evaluate(request: UserRequest):
    # Production agent handles the request
    prod_response = await production_agent.run(request)

    # Shadow agent runs in parallel (no user impact)
    shadow_response = await shadow_agent.run(request)

    # Log comparison for offline analysis
    await log_comparison(
        request=request,
        prod=prod_response,
        shadow=shadow_response,
        metrics=["latency", "cost", "quality_score"]
    )

    return prod_response  # Only production response goes to user
```

**2. A/B Testing for Agents**
Split traffic to measure real-world performance differences:

```python
@ab_test(experiment="agent_v2_rollout", traffic_split=0.1)
async def handle_request(request: UserRequest, variant: str):
    if variant == "control":
        return await agent_v1.run(request)
    else:
        return await agent_v2.run(request)
```

**3. Evaluation-Gated Deployments**
Block deployments that fail quality thresholds:

```yaml
# .github/workflows/deploy.yml
- name: Run Agent Evals
  run: |
    promptfoo eval --config eval.yaml

- name: Check Quality Gate
  run: |
    # Fail if accuracy drops below threshold
    if [ $(cat results.json | jq '.accuracy') -lt 0.85 ]; then
      echo "Quality gate failed: accuracy below 85%"
      exit 1
    fi
```

**4. Regression Testing for Prompt Changes**
Every prompt change should trigger evaluation:

```python
# Track prompt versions and their performance
class PromptRegistry:
    def __init__(self):
        self.versions = {}
        self.baseline_metrics = {}

    def register_prompt(self, name: str, version: str, prompt: str):
        self.versions[f"{name}:{version}"] = prompt

    async def evaluate_regression(self, name: str, new_version: str):
        baseline = self.baseline_metrics[name]
        new_metrics = await run_eval_suite(name, new_version)

        regression = {
            "accuracy_delta": new_metrics.accuracy - baseline.accuracy,
            "latency_delta": new_metrics.p95_latency - baseline.p95_latency,
            "cost_delta": new_metrics.cost_per_request - baseline.cost_per_request,
        }

        if regression["accuracy_delta"] < -0.02:  # 2% accuracy drop
            raise RegressionError(f"Accuracy regression: {regression}")

        return regression
```

<Callout type="warning">
  **The Cost of Skipping Production Evals**: Teams that skip continuous
  evaluation often discover regressions from user complaints—days or weeks after
  deployment. By then, the damage to user trust is done. Invest in automated
  monitoring early.
</Callout>
