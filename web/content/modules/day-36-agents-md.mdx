## The Problem: Configuration Fragmentation

Before standardization, developers juggled multiple configuration files for different AI tools:

```
my-project/
├── .cursorrules          # Cursor IDE
├── CLAUDE.md             # Claude Code
├── .gemini/settings.json # Gemini CLI
├── .aider.conf.yml       # Aider
└── copilot-instructions.md # GitHub Copilot
```

Each file contained similar information but in different formats. When coding standards changed, you updated five files. When onboarding a new tool, you wrote yet another config.

<Callout type="insight">
  **The Solution**: AGENTS.md emerged as a unified standard—one file that any AI
  coding agent can read. Over 60,000 GitHub repositories now use it, and major
  tools are converging on this format.
</Callout>

---

## What Are These Files?

Think of AGENTS.md and CLAUDE.md as **README files for AI agents**. Just as README.md tells human developers how to work with your project, these files tell AI assistants:

- What the project does and how it's structured
- Which coding standards to follow
- What tools and commands are available
- What patterns to avoid

| File Type   | Purpose                          | Primary Audience        |
| :---------- | :------------------------------- | :---------------------- |
| README.md   | Project overview for humans      | Human developers        |
| AGENTS.md   | Universal AI agent configuration | All AI coding tools     |
| CLAUDE.md   | Claude-specific instructions     | Claude Code, Claude API |

## File Precedence: How Configs Are Applied

AI tools read configuration files in a specific order, with later files overriding earlier ones:

### Precedence Order (Lowest to Highest)

1. **Enterprise policies** — Organization-wide rules (cannot be overridden)
2. **Personal defaults** — Your global preferences (`~/.claude/CLAUDE.md`)
3. **Project root** — Repository-level configuration (`/repo/AGENTS.md`)
4. **Subdirectory** — Path-specific rules (`/repo/services/api/AGENTS.md`)
5. **Override files** — `AGENTS.override.md` takes highest precedence

<Callout type="warning">
  **Enterprise Override**: In corporate environments, enterprise policies are
  applied last and cannot be overridden by personal or project settings. This
  ensures compliance with security and coding standards.
</Callout>

## File Structure and Placement

### Global Configuration

Personal defaults that apply to all your projects:

```bash
# Claude Code
~/.claude/CLAUDE.md

# Cursor
~/.cursor/rules/global.mdc

# Kiro
~/.kiro/steering/global.md
```

**Example global config:**

```markdown
# ~/.claude/CLAUDE.md

## My Coding Preferences

- Always use TypeScript strict mode
- Prefer functional programming patterns
- Use pnpm for package management
- Write tests before implementation (TDD)

## Communication Style

- Be concise in explanations
- Show code examples over lengthy descriptions
- Ask clarifying questions before large refactors
```

### Project-Level Configuration

Place at repository root for project-wide rules:

```
my-project/
├── AGENTS.md      # Universal (recommended)
├── CLAUDE.md      # Claude-specific (optional)
└── .cursorrules   # Cursor-specific (legacy)
```

### Subdirectory Configuration

For monorepos or projects with distinct areas:

```
monorepo/
├── AGENTS.md                    # Root defaults
├── packages/
│   ├── frontend/
│   │   └── AGENTS.md            # React/TypeScript rules
│   ├── backend/
│   │   └── AGENTS.md            # Python/FastAPI rules
│   └── shared/
│       └── AGENTS.md            # Shared library rules
└── services/
    └── payments/
        └── AGENTS.override.md   # Strict security rules
```

## Key Sections to Include

A well-structured configuration file includes these sections:

### 1. Project Context

```markdown
## Project Overview

This is a Next.js 14 e-commerce platform with:

- App Router architecture
- PostgreSQL database via Prisma
- Stripe payment integration
- Redis for session management

## Tech Stack

- Next.js 14.2.x
- TypeScript 5.4
- Tailwind CSS 3.4
- Node.js 20 LTS
```

### 2. Coding Standards

```markdown
## Code Style

- Use single quotes for strings
- No semicolons (Prettier handles this)
- Prefer `const` over `let`
- Use named exports, not default exports
- Maximum line length: 100 characters

## Naming Conventions

- Components: PascalCase (`UserProfile.tsx`)
- Hooks: camelCase with `use` prefix (`useAuth.ts`)
- Utils: camelCase (`formatDate.ts`)
- Constants: SCREAMING_SNAKE_CASE
```

### 3. Tool Usage and Commands

```markdown
## Available Commands

- `pnpm dev` — Start development server
- `pnpm test` — Run test suite
- `pnpm test:watch` — Run tests in watch mode
- `pnpm lint` — Run ESLint
- `pnpm typecheck` — Run TypeScript compiler

## Before Committing

1. Run `pnpm lint` and fix all errors
2. Run `pnpm typecheck` with no errors
3. Run `pnpm test` — all tests must pass
4. Format with `pnpm format`
```

### 4. Forbidden Patterns

```markdown
## Do NOT

- Use `any` type in TypeScript
- Commit `.env` files or secrets
- Use `console.log` in production code
- Modify `package.json` without discussion
- Skip writing tests for new features
- Use synchronous file operations in API routes

## Security Rules

- Never hardcode API keys or credentials
- Always validate user input
- Use parameterized queries (no string concatenation for SQL)
- Sanitize all data before rendering
```

## Comparison: AGENTS.md vs CLAUDE.md vs .cursorrules

<div className="overflow-x-auto">

| Feature                | AGENTS.md                  | CLAUDE.md                | .cursorrules           |
| :--------------------- | :------------------------- | :----------------------- | :--------------------- |
| **Tool Support**       | Universal (60k+ repos)     | Claude Code, Claude API  | Cursor IDE only        |
| **Standardization**    | Industry standard (AAIF)   | Anthropic convention     | Cursor-specific        |
| **Hierarchical**       | ✅ Full support            | ✅ Supported             | ❌ Single file only    |
| **Override Files**     | ✅ `.override.md` support  | ❌ Not supported         | ❌ Not supported       |
| **Machine-Readable**   | ✅ JSON/YAML metadata      | ⚠️ Limited               | ❌ Plain text only     |
| **Enterprise Support** | ✅ Policy enforcement      | ✅ Via Claude Enterprise | ❌ No enterprise tier  |
| **Recommended For**    | Cross-tool compatibility   | Claude-only workflows    | Legacy Cursor projects |

</div>

<Callout type="tip">
  **Recommendation**: Use AGENTS.md as your primary configuration file for
  maximum compatibility. Add CLAUDE.md only if you need Claude-specific
  instructions that don't apply to other tools.
</Callout>

## Cross-Tool Compatibility

### Making One File Work Everywhere

Most modern AI tools now recognize AGENTS.md:

```markdown
# AGENTS.md (works with Cursor, Claude Code, Windsurf, Kiro, Aider, Codex)

## Project: E-Commerce Platform

### Tech Stack

- Next.js 14, TypeScript 5.4, Tailwind CSS
- Database: PostgreSQL with Prisma ORM
- Auth: NextAuth.js with OAuth providers

### Commands

- Install: `pnpm install`
- Dev: `pnpm dev`
- Test: `pnpm test`
- Build: `pnpm build`

### Code Standards

- Strict TypeScript (no `any`)
- Functional React components only
- Use server actions for mutations
- Colocate tests with source files

### Forbidden

- No `var` declarations
- No default exports (except pages)
- No inline styles (use Tailwind)
- No `// @ts-ignore` comments
```

### Tool-Specific Fallbacks

For tools that don't yet support AGENTS.md, create symlinks:

```bash
# Create AGENTS.md as the source of truth
# Then symlink for backward compatibility

ln -s AGENTS.md CLAUDE.md
ln -s AGENTS.md .cursorrules
```

Or configure tools to read AGENTS.md:

**Aider** (`.aider.conf.yml`):

```yaml
read: AGENTS.md
```

**Gemini CLI** (`.gemini/settings.json`):

```json
{
  "contextFileName": "AGENTS.md"
}
```

## Best Practices

### Keep It Concise (Under 150-200 Lines)

AI tools have context limits. A bloated config wastes tokens and dilutes important instructions.

```markdown
<!-- ❌ Too verbose -->

## Testing

When writing tests, you should always make sure to follow our testing
guidelines which state that every function should have at least one test
and preferably multiple tests covering different scenarios including
edge cases and error conditions...

<!-- ✅ Concise and actionable -->

## Testing

- Every function needs tests
- Cover happy path + 2 edge cases
- Run `pnpm test` before committing
```

### Be Specific, Not Abstract

```markdown
<!-- ❌ Vague -->

Follow best practices for error handling.

<!-- ✅ Specific -->

## Error Handling

- Wrap async operations in try/catch
- Use custom error classes from `src/errors/`
- Log errors with `logger.error()`, not console
- Return user-friendly messages, log technical details
```

### Include Examples

```markdown
## API Response Format

Always return responses in this structure:

```json
{
  "success": true,
  "data": { ... },
  "meta": {
    "timestamp": "2025-01-15T10:30:00Z",
    "requestId": "req_abc123"
  }
}
```

For errors:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Email is required",
    "field": "email"
  }
}
```
```

## Monorepo Support

For large codebases, use hierarchical configs:

```
enterprise-app/
├── AGENTS.md                      # Company-wide standards
│
├── apps/
│   ├── web/
│   │   └── AGENTS.md              # Next.js frontend rules
│   ├── mobile/
│   │   └── AGENTS.md              # React Native rules
│   └── admin/
│       └── AGENTS.md              # Admin dashboard rules
│
├── packages/
│   ├── ui/
│   │   └── AGENTS.md              # Component library rules
│   └── api-client/
│       └── AGENTS.md              # API client rules
│
└── services/
    └── payments/
        ├── AGENTS.md              # Payment service rules
        └── AGENTS.override.md     # PCI compliance overrides
```

**Root AGENTS.md** (shared standards):

```markdown
# Enterprise App Standards

## Universal Rules

- TypeScript strict mode everywhere
- All PRs require tests
- No secrets in code

## Monorepo Commands

- `pnpm install` — Install all dependencies
- `pnpm build` — Build all packages
- `pnpm test` — Run all tests
```

**Subdirectory AGENTS.md** (specific overrides):

```markdown
# apps/web/AGENTS.md

## Frontend-Specific Rules

Inherits from root AGENTS.md, plus:

- Use App Router (not Pages Router)
- Server Components by default
- Client Components only when needed
- Use `next/image` for all images
```

## Key Takeaways

<Callout type="success">

**What You Learned**:

1. **AGENTS.md is the universal standard** — Works across Cursor, Claude Code, Windsurf, Kiro, and more
2. **Precedence matters** — Enterprise > Personal > Project > Subdirectory > Override
3. **Keep configs concise** — Under 150-200 lines, specific and actionable
4. **Key sections**: Project context, coding standards, commands, forbidden patterns
5. **Monorepos need hierarchy** — Root defaults with subdirectory overrides
6. **Cross-tool compatibility** — Use AGENTS.md as source of truth, symlink for legacy tools

</Callout>
