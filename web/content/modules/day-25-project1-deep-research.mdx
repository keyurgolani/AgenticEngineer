### Acceptance Criteria

#### US-01: Topic Submission and Report Generation

- **Given** a user submits a well-defined topic
- **When** the research workflow completes
- **Then** a markdown report is generated with:
  - Minimum 1,500 words for standard depth
  - At least 5 unique sources cited
  - Executive summary and key takeaways sections
  - Report saved to `output/` directory with timestamped filename

#### US-02: Clarification Flow

- **Given** a user submits a vague topic (e.g., "AI")
- **When** the clarification agent evaluates the topic
- **Then** the system:
  - Returns 2-3 specific clarifying questions
  - Pauses execution until user responds
  - Incorporates responses into the research brief

#### US-03: Brief Approval Gate

- **Given** a research brief is generated
- **When** the system reaches the approval checkpoint
- **Then** the user can:
  - View proposed sub-topics and estimated cost
  - Approve to continue
  - Modify sub-topics before proceeding
  - Cancel the research entirely

#### US-04: Progress Updates

- **Given** research is in progress
- **When** each phase completes
- **Then** the system emits status updates including:
  - Current phase (scoping/research/writing)
  - Sub-topics completed vs. remaining
  - Estimated time to completion

#### US-05: Cost Limits

- **Given** a cost limit is configured (e.g., $2.00)
- **When** estimated cost exceeds the limit
- **Then** the system:
  - Pauses before the next expensive operation
  - Notifies the user of current spend
  - Allows user to approve additional spend or terminate

#### US-06: Source Citations

- **Given** a completed research report
- **When** the report is reviewed
- **Then** every factual claim includes an inline citation in format `[Source: domain.com]`

## 8.1 The Three-Phase Architecture

Production deep research systems share a common pattern: **Scope → Research → Write**. Each phase has distinct responsibilities and failure modes.

### Why Three Phases?

{/* IMAGE_PLACEHOLDER: An infographic showing three phases as connected gears or pipeline stages. Phase 1 (Scoping) shows a funnel narrowing down from vague to specific. Phase 2 (Research) shows multiple parallel arrows branching out and converging. Phase 3 (Writing) shows a single stream with feedback loops. Include time savings and cost reduction metrics for each phase. Style: Clean, modern infographic with icons and data visualization. */}

**Phase 1 (Scoping)** prevents wasted computation. Research from OpenAI and Perplexity shows that users rarely provide sufficient context in their initial request. A 30-second clarification can save 10 minutes of misdirected research and significantly reduce costs.

**Phase 2 (Research)** benefits from parallelization. Independent sub-topics can be researched simultaneously, but the supervisor must coordinate to avoid gaps and redundancy. This is where LangGraph's `Send` API shines.

**Phase 3 (Writing)** requires coherence. LangChain's experiments with Open Deep Research found that parallel section writing produces disjointed reports. A single writer with all context produces better results.

### Comparing Deep Research Architectures

| Aspect              | OpenAI Deep Research       | Perplexity                 | Google Gemini              | Our Implementation     |
| :------------------ | :------------------------- | :------------------------- | :------------------------- | :--------------------- |
| **Reasoning Model** | o3 (extended thinking)     | DeepSeek R1 + TTC          | Gemini 3 Pro (MoE)         | GPT-4o / Claude 3.5    |
| **Search Strategy** | Iterative, self-correcting | Dozens of parallel queries | Multi-step with validation | Parallel per sub-topic |
| **Source Count**    | 100+ sources               | Hundreds of sources        | 50+ sources                | 15-30 sources          |
| **Runtime**         | 5-30 minutes               | 2-4 minutes                | Up to 60 minutes           | 3-10 minutes           |
| **Cost**            | ~$0.10-0.50/query          | Subscription               | Subscription               | $0.50-2.00/report      |

## 8.3 State Design with Context Engineering

The state schema is critical for multi-agent coordination. We apply **context engineering principles** from Day 02 to prevent token bloat.

```python
# models/state.py
from typing import TypedDict, Annotated, Optional, List
from datetime import datetime
import operator

class ResearchState(TypedDict):
    """Production state for Deep Research Agent.

    Design Principles:
    1. Separate concerns by phase
    2. Use reducers for parallel aggregation
    3. Track metadata for debugging and cost control
    """
    # === Phase 1: Scoping ===
    topic: str
    clarifying_questions: List[str]
    user_responses: List[str]
    research_brief: str  # JSON string of structured brief

    # === Phase 2: Research ===
    sub_topics: List[str]
    # operator.ior merges dicts from parallel researchers
    research_findings: Annotated[dict, operator.ior]
    # operator.add accumulates sources from all researchers
    sources: Annotated[List[str], operator.add]
    research_gaps: List[str]  # Identified by supervisor

    # === Phase 3: Writing ===
    draft: str
    critique: Optional[str]
    revision_count: int
    final_report: str

    # === Control Flow ===
    status: str
    current_phase: str

    # === Metadata (for debugging and cost tracking) ===
    started_at: Optional[str]
    completed_at: Optional[str]
    total_tokens_used: int
    estimated_cost_usd: float
    errors: List[str]

    # === Observability ===
    trace_id: Optional[str]
    span_ids: List[str]
```

<Callout type="tip">
**Why `operator.ior` for findings?** When parallel researchers return `{"topic_a": "findings..."}` and `{"topic_b": "findings..."}`, the `ior` reducer merges them into a single dict. Without this, the last researcher would overwrite all previous findings.
</Callout>

### Pydantic Models for Structured Output

```python
# models/schemas.py
from pydantic import BaseModel, Field
from typing import List
from enum import Enum

class ResearchDepth(str, Enum):
    BRIEF = "brief"           # ~1000 words
    STANDARD = "standard"     # ~3000 words
    COMPREHENSIVE = "comprehensive"  # ~5000+ words

class ConfidenceLevel(str, Enum):
    HIGH = "high"
    MEDIUM = "medium"
    LOW = "low"

class ResearchBrief(BaseModel):
    """Structured brief that guides the entire research process."""
    title: str = Field(description="Clear, specific title for the research")
    objective: str = Field(description="The core question we're answering")
    sub_topics: List[str] = Field(
        description="3-5 independent sub-topics for parallel research",
        min_length=3,
        max_length=7
    )
    key_questions: dict = Field(
        description="Mapping of sub-topic to specific questions to answer"
    )
    success_criteria: str = Field(
        description="How we know the research is complete and sufficient"
    )
    estimated_depth: ResearchDepth = Field(
        description="Expected report length based on topic complexity"
    )
    target_audience: str = Field(
        default="technical professionals",
        description="Who will read this report"
    )

class ResearchFindings(BaseModel):
    """Structured output from a researcher."""
    sub_topic: str
    key_findings: List[str] = Field(description="3-5 key facts or insights")
    summary: str = Field(description="300-500 word synthesis")
    sources: List[str] = Field(description="URLs of sources used")
    confidence: ConfidenceLevel = Field(description="Confidence in findings")
    gaps: List[str] = Field(description="Questions that couldn't be answered")
    contradictions: List[str] = Field(
        default_factory=list,
        description="Conflicting information found across sources"
    )

class CritiqueResult(BaseModel):
    """Structured critique from the reviewer."""
    score: int = Field(ge=1, le=10, description="Quality score 1-10")
    word_count: int
    meets_brief: bool = Field(description="Does it address the research brief?")
    source_quality: int = Field(ge=1, le=10, description="Quality of citations")
    strengths: List[str]
    issues: List[str]
    suggestions: List[str]
    factual_concerns: List[str] = Field(
        default_factory=list,
        description="Claims that may need verification"
    )
    approved: bool = Field(description="Ready for delivery?")
```

```python
CLARIFICATION_PROMPT = """You are a research assistant preparing to conduct deep research.

The user wants to research: {topic}

Your job is to determine if you have enough context to proceed. Consider:
1. Is the scope clear? (Too broad like "AI" or appropriately focused?)
2. Is there a specific angle, perspective, or use case?
3. What time period should we focus on? (Historical, current, future?)
4. Are there specific aspects to include or exclude?
5. Who is the target audience for this research?

If the topic is sufficiently clear for comprehensive research, respond exactly with:
READY TO RESEARCH

Otherwise, ask 2-3 specific clarifying questions. Be concise and friendly.
Do NOT ask unnecessary questions if the topic is already well-defined."""

BRIEF_GENERATION_PROMPT = """Create a comprehensive research brief for the following topic.

Topic: {topic}
{clarifications}

Requirements:
1. Create 3-5 INDEPENDENT sub-topics that can be researched in parallel
2. Each sub-topic should be self-contained (no dependencies on others)
3. Define specific questions each sub-topic should answer
4. Set clear success criteria for when research is complete
5. Estimate the appropriate depth based on topic complexity

The brief will guide multiple research agents working in parallel."""

class ScopingAgent:
    def __init__(self, model: str = "gpt-4o-mini"):
        self.llm = ChatOpenAI(model=model, temperature=0.3)
        self.structured_llm = ChatOpenAI(model="gpt-4o").with_structured_output(
            ResearchBrief
        )

    def check_clarity(self, topic: str) -> tuple[bool, str]:
        """Check if topic needs clarification."""
        prompt = ChatPromptTemplate.from_template(CLARIFICATION_PROMPT)
        chain = prompt | self.llm

        response = chain.invoke({"topic": topic})
        content = response.content.strip()

        is_ready = "READY TO RESEARCH" in content
        return is_ready, content

    def generate_brief(self, topic: str, clarifications: str = "") -> ResearchBrief:
        """Generate structured research brief."""
        prompt = ChatPromptTemplate.from_template(BRIEF_GENERATION_PROMPT)
        chain = prompt | self.structured_llm

        clarification_text = f"\nUser clarifications: {clarifications}" if clarifications else ""

        return chain.invoke({
            "topic": topic,
            "clarifications": clarification_text
        })

def clarification_node(state: ResearchState) -> dict:
    """Node: Check if topic needs clarification."""
    agent = ScopingAgent()
    is_ready, response = agent.check_clarity(state["topic"])

    if is_ready:
        return {
            "status": "ready_for_brief",
            "current_phase": "scoping"
        }
    else:
        return {
            "clarifying_questions": [response],
            "status": "needs_clarification",
            "current_phase": "scoping"
        }

def brief_generation_node(state: ResearchState) -> dict:
    """Node: Generate the research brief."""
    agent = ScopingAgent()

    # Combine any user responses
    clarifications = "\n".join(state.get("user_responses", []))

    brief = agent.generate_brief(state["topic"], clarifications)

    return {
        "research_brief": brief.model_dump_json(),
        "sub_topics": brief.sub_topics,
        "status": "brief_complete",
        "current_phase": "research"
    }
```

  **Production Tip:** In a real application, the `needs_clarification` status

  provides answers, and the graph resumes. We'll implement this pattern in

## 8.5 Phase 2: Parallel Research with Context Isolation

This is where the production architecture shines. We use LangGraph's `Send` API to fan out research to parallel workers, each with **isolated context**.

### The Context Isolation Pattern

```python
# agents/research.py
from langchain_openai import ChatOpenAI
from langchain_community.tools.tavily_search import TavilySearchResults
from langchain_core.prompts import ChatPromptTemplate
from langgraph.constants import Send
from models.schemas import ResearchFindings
from models.state import ResearchState
from typing import List
import json

RESEARCHER_PROMPT = """You are a focused research analyst investigating ONE specific sub-topic.

Sub-topic: {sub_topic}
Questions to answer: {questions}

Search Results:
{search_results}

Instructions:
1. Focus ONLY on your assigned sub-topic
2. Synthesize information from multiple sources
3. Note specific facts, statistics, and expert opinions
4. Cite sources accurately with URLs
5. Identify any questions you couldn't answer (gaps)
6. Flag any contradictory information across sources

Do NOT research other topics—that's handled by other agents."""

class ResearcherAgent:
    def __init__(self, model: str = "gpt-4o-mini"):
        self.llm = ChatOpenAI(model=model, temperature=0.2)
        self.structured_llm = self.llm.with_structured_output(ResearchFindings)
        self.search = TavilySearchResults(max_results=5)

    def _generate_queries(self, sub_topic: str, questions: List[str]) -> List[str]:
        """Generate targeted search queries."""
        query_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.5)

        prompt = f"""Generate 3 specific search queries to research:
Topic: {sub_topic}
Questions to answer: {questions}

Return only the queries, one per line. Make them specific and searchable.
Include year "2025" or "2024" for recent information where relevant."""

        response = query_llm.invoke(prompt)
        return [q.strip() for q in response.content.strip().split('\n') if q.strip()][:3]

    def research(self, sub_topic: str, questions: List[str]) -> ResearchFindings:
        """Research a single sub-topic with focused context."""
        # Generate and execute searches
        queries = self._generate_queries(sub_topic, questions)

        all_results = []
        for query in queries:
            try:
                results = self.search.invoke(query)
                all_results.extend(results)
            except Exception as e:
                print(f"Search error for '{query}': {e}")

        # Deduplicate by URL
        seen_urls = set()
        unique_results = []
        for r in all_results:
            url = r.get('url', '')
            if url and url not in seen_urls:
                seen_urls.add(url)
                unique_results.append(r)

        # Synthesize with structured output
        prompt = ChatPromptTemplate.from_template(RESEARCHER_PROMPT)
        chain = prompt | self.structured_llm

        return chain.invoke({
            "sub_topic": sub_topic,
            "questions": "\n".join(f"- {q}" for q in questions),
            "search_results": json.dumps(unique_results[:8], indent=2)
        })
```

### Supervisor and Fan-Out Implementation

```python
# agents/research.py (continued)

def supervisor_node(state: ResearchState) -> dict:
    """Supervisor: Coordinate research and check completeness."""
    findings = state.get("research_findings", {})
    sub_topics = state.get("sub_topics", [])

    # Check what's missing
    missing = [t for t in sub_topics if t not in findings]

    if missing:
        return {"status": "researching"}

    # All topics researched—evaluate completeness
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.1)

    brief = state.get("research_brief", "{}")
    findings_summary = "\n".join([
        f"**{topic}**: {data.get('summary', '')[:300]}..."
        for topic, data in findings.items()
        if isinstance(data, dict)
    ])

    eval_prompt = f"""Research Brief: {brief}

Findings Summary:
{findings_summary}

Evaluate: Do we have sufficient information to write a comprehensive report?

Respond with either:
- "SUFFICIENT" if ready to write
- "GAPS: [list specific missing information]" if more research needed"""

    response = llm.invoke(eval_prompt)

    if "SUFFICIENT" in response.content:
        return {"status": "research_complete", "current_phase": "writing"}
    else:
        # Extract gaps for potential follow-up research
        gaps = response.content.replace("GAPS:", "").strip()
        return {
            "research_gaps": [gaps],
            "status": "research_complete",  # Proceed anyway to avoid infinite loops
            "current_phase": "writing"
        }

def route_to_researchers(state: ResearchState) -> List[Send]:
    """Fan-out: Send each sub-topic to a parallel researcher.

    KEY PATTERN: Context Isolation
    Each researcher receives ONLY:
    - Their assigned sub-topic
    - Questions specific to that topic
    - The research brief (for context)

    They do NOT receive:
    - Other researchers' findings
    - Full conversation history
    - Unrelated state
    """
    if state["status"] != "researching":
        return []

    findings = state.get("research_findings", {})
    sub_topics = state.get("sub_topics", [])

    # Parse brief to get questions per topic
    try:
        brief = json.loads(state.get("research_brief", "{}"))
        key_questions = brief.get("key_questions", {})
    except json.JSONDecodeError:
        key_questions = {}

    # Only research topics we don't have findings for
    missing = [t for t in sub_topics if t not in findings]

    return [
        Send("researcher", {
            # ISOLATED CONTEXT: Only what this researcher needs
            "sub_topic": topic,
            "questions": key_questions.get(topic, [f"What are the key aspects of {topic}?"]),
            "brief_objective": brief.get("objective", state["topic"])
        })
        for topic in missing
    ]

def researcher_node(state: dict) -> dict:
    """Individual researcher node (receives isolated context)."""
    agent = ResearcherAgent()

    sub_topic = state["sub_topic"]
    questions = state.get("questions", [])

    print(f"🔍 Researching: {sub_topic}")

    findings = agent.research(sub_topic, questions)

    return {
        "research_findings": {sub_topic: findings.model_dump()},
        "sources": findings.sources
    }
```

<Callout type="info">
  **Context Isolation in Action:** Notice how `researcher_node` receives a
  minimal dict with only `sub_topic`, `questions`, and `brief_objective`. It
  never sees other researchers' findings or the full state. This prevents
  context pollution and reduces token usage by ~60% compared to passing full
  state.
</Callout>

### Understanding LangGraph's Super-Steps

{/* IMAGE_PLACEHOLDER: A step-by-step visualization of LangGraph's super-step execution model. Show 3 super-steps as horizontal layers: Step 1 (supervisor runs), Step 2 (multiple researchers run in parallel with sync barrier), Step 3 (supervisor evaluates). Use a timeline view with synchronization points clearly marked. Include the Pregel model reference with a small Google logo. Style: Technical diagram with clear temporal flow, use different colors for each step. */}

LangGraph executes in discrete **super-steps**: nodes scheduled together run in parallel, then the system synchronizes before the next step. This is based on the Pregel model (used by Google for large-scale graph processing).

```python
# How parallel execution works in LangGraph:
#
# Super-step 1: supervisor_node runs
#   - Returns status="researching"
#   - route_to_researchers returns [Send("researcher", {...}), Send("researcher", {...}), ...]
#
# Super-step 2: All researcher nodes run IN PARALLEL
#   - Each receives isolated context
#   - Each returns {"research_findings": {topic: findings}, "sources": [...]}
#   - Reducers (operator.ior, operator.add) merge results
#
# Super-step 3: supervisor_node runs again
#   - Sees merged findings from all researchers
#   - Evaluates completeness
#   - Routes to writer or requests more research
```

<Callout type="tip">
  **Performance Insight:** With 5 sub-topics researched in parallel, total
  research time is ~45 seconds (the slowest researcher) instead of ~225 seconds
  (5 × 45s sequential). This 5x speedup is why the fan-out pattern is essential
  for production.
</Callout>

## 8.6 Phase 3: Writing with Quality Loops

{/* IMAGE_PLACEHOLDER: A circular feedback loop diagram showing the Writer-Critic cycle. Show: Writer generates draft → Critic evaluates (with scoring rubric visible) → Decision point (Approve/Revise) → If revise, loop back to Writer with critique. Include a counter showing "Revision 1 of 3" and quality score progression: "6.5 → 7.8 → 8.5". Style: Circular flow diagram with quality metrics visualization. */}

The writing phase uses a **reflection pattern** where a Critic reviews the Writer's output and requests revisions until quality thresholds are met.

```python
# agents/writing.py
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from models.schemas import CritiqueResult
from models.state import ResearchState
import json

WRITER_SYSTEM = """You are an expert technical writer producing research reports.

Writing Guidelines:
1. Write in a clear, authoritative voice
2. Use specific data points and examples from the research
3. Create smooth transitions between sections
4. Cite sources inline using [Source: domain.com] format
5. Match the depth specified in the research brief
6. Include an executive summary and key takeaways
7. Flag any areas where sources conflicted"""

WRITER_PROMPT = """Write a comprehensive research report.

# Research Brief
{brief}

# Research Findings
{findings}

# Previous Critique (if revising)
{critique}

# Instructions
{instruction}

Write the complete report now."""

CRITIC_PROMPT = """You are a senior editor reviewing a research report.

# Research Brief (Success Criteria)
{brief}

# Report to Review
{report}

Evaluate on:
1. **Completeness**: Does it address all sub-topics from the brief?
2. **Accuracy**: Are claims supported by cited sources?
3. **Depth**: Does it meet the expected word count and detail level?
4. **Clarity**: Is it well-organized with smooth transitions?
5. **Citations**: Are sources properly cited inline?
6. **Factual Concerns**: Are there claims that seem unsupported or questionable?

Scoring:
- 9-10: Publication ready
- 7-8: Minor revisions needed
- 5-6: Significant revisions needed
- 1-4: Major rewrite required

Approve only if score >= 8."""

class WriterAgent:
    def __init__(self, model: str = "gpt-4o"):
        self.llm = ChatOpenAI(model=model, temperature=0.7)

    def write(
        self,
        brief: str,
        findings: dict,
        critique: str = None,
        is_revision: bool = False
    ) -> str:
        """Write or revise the report."""
        # Format findings for the prompt
        findings_text = ""
        for topic, data in findings.items():
            if isinstance(data, dict):
                findings_text += f"\n## {topic}\n"
                findings_text += f"Summary: {data.get('summary', '')}\n"
                findings_text += "Key Findings:\n"
                for finding in data.get('key_findings', []):
                    findings_text += f"- {finding}\n"
                findings_text += f"Sources: {', '.join(data.get('sources', []))}\n"
                if data.get('contradictions'):
                    findings_text += f"Contradictions: {', '.join(data.get('contradictions', []))}\n"

        instruction = (
            "Revise the report addressing each issue from the critique."
            if is_revision else
            "Write a comprehensive report based on the research findings."
        )

        prompt = ChatPromptTemplate.from_messages([
            ("system", WRITER_SYSTEM),
            ("human", WRITER_PROMPT)
        ])

        chain = prompt | self.llm

        response = chain.invoke({
            "brief": brief,
            "findings": findings_text,
            "critique": critique or "N/A - First draft",
            "instruction": instruction
        })

        return response.content

class CriticAgent:
    def __init__(self, model: str = "gpt-4o"):
        self.llm = ChatOpenAI(model=model, temperature=0.1)
        self.structured_llm = self.llm.with_structured_output(CritiqueResult)

    def critique(self, brief: str, report: str) -> CritiqueResult:
        """Provide structured critique of the report."""
        prompt = ChatPromptTemplate.from_template(CRITIC_PROMPT)
        chain = prompt | self.structured_llm

        return chain.invoke({
            "brief": brief,
            "report": report[:15000]  # Truncate for context limits
        })

def writer_node(state: ResearchState) -> dict:
    """Node: Write or revise the report."""
    agent = WriterAgent()

    is_revision = state.get("critique") is not None

    print(f"✍️ {'Revising' if is_revision else 'Writing'} report...")

    draft = agent.write(
        brief=state.get("research_brief", ""),
        findings=state.get("research_findings", {}),
        critique=state.get("critique"),
        is_revision=is_revision
    )

    word_count = len(draft.split())
    print(f"   Draft complete: {word_count} words")

    return {
        "draft": draft,
        "status": "draft_complete"
    }

def critic_node(state: ResearchState) -> dict:
    """Node: Review the draft and decide next action."""
    agent = CriticAgent()

    print("🔍 Reviewing draft...")

    result = agent.critique(
        brief=state.get("research_brief", ""),
        report=state.get("draft", "")
    )

    print(f"   Score: {result.score}/10 | Approved: {result.approved}")

    if result.approved:
        return {
            "final_report": state["draft"],
            "status": "approved",
            "critique": None
        }
    else:
        # Format critique for the writer
        critique_text = f"""Score: {result.score}/10

Issues to Address:
{chr(10).join(f'- {issue}' for issue in result.issues)}

Suggestions:
{chr(10).join(f'- {s}' for s in result.suggestions)}

Factual Concerns:
{chr(10).join(f'- {c}' for c in result.factual_concerns) if result.factual_concerns else 'None identified'}"""

        return {
            "critique": critique_text,
            "revision_count": state.get("revision_count", 0) + 1,
            "status": "needs_revision"
        }

def should_continue_writing(state: ResearchState) -> str:
    """Routing: Continue revising or finalize?"""
    if state["status"] == "approved":
        return "finalize"

    # Prevent infinite loops
    if state.get("revision_count", 0) >= 3:
        print("⚠️ Max revisions reached, finalizing current draft")
        return "finalize"

    return "revise"

def finalize_node(state: ResearchState) -> dict:
    """Node: Finalize the report."""
    from datetime import datetime

    final = state.get("final_report") or state.get("draft", "")

    # Add metadata footer
    final += f"\n\n---\n*Generated by Deep Research Agent on {datetime.now().strftime('%Y-%m-%d')}*"
    final += f"\n*Sources consulted: {len(set(state.get('sources', [])))}*"

    return {
        "final_report": final,
        "status": "complete",
        "completed_at": datetime.now().isoformat()
    }
```

## 8.7 Wiring the Complete Graph

Now we assemble all phases into a complete LangGraph workflow with proper routing and checkpointing.

```python
# main.py
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from models.state import ResearchState
from agents.scoping import clarification_node, brief_generation_node
from agents.research import supervisor_node, researcher_node, route_to_researchers
from agents.writing import writer_node, critic_node, finalize_node, should_continue_writing
from datetime import datetime
from pathlib import Path

def build_research_graph(use_memory: bool = True):
    """Build the complete three-phase research graph."""

    workflow = StateGraph(ResearchState)

    # === Phase 1: Scoping ===
    workflow.add_node("clarify", clarification_node)
    workflow.add_node("generate_brief", brief_generation_node)

    # === Phase 2: Research ===
    workflow.add_node("supervisor", supervisor_node)
    workflow.add_node("researcher", researcher_node)

    # === Phase 3: Writing ===
    workflow.add_node("writer", writer_node)
    workflow.add_node("critic", critic_node)
    workflow.add_node("finalize", finalize_node)

    # === Edges ===

    # Start with clarification
    workflow.add_edge(START, "clarify")

    # Clarification routing
    workflow.add_conditional_edges(
        "clarify",
        lambda s: "generate_brief" if s["status"] == "ready_for_brief" else END,
        {"generate_brief": "generate_brief", END: END}
    )

    # Brief leads to research
    workflow.add_edge("generate_brief", "supervisor")

    # Supervisor fans out to researchers
    workflow.add_conditional_edges(
        "supervisor",
        route_to_researchers,
        ["researcher"]
    )

    # Researchers report back to supervisor
    workflow.add_edge("researcher", "supervisor")

    # Supervisor routes to writer when complete
    workflow.add_conditional_edges(
        "supervisor",
        lambda s: "writer" if s["status"] == "research_complete" else "supervisor",
        {"writer": "writer", "supervisor": "supervisor"}
    )

    # Write-critique loop
    workflow.add_edge("writer", "critic")
    workflow.add_conditional_edges(
        "critic",
        should_continue_writing,
        {"revise": "writer", "finalize": "finalize"}
    )

    workflow.add_edge("finalize", END)

    # Compile with checkpointing
    checkpointer = MemorySaver() if use_memory else None

    return workflow.compile(checkpointer=checkpointer)

def run_research(topic: str, thread_id: str = None) -> dict:
    """Execute the research workflow."""

    print("=" * 60)
    print("🔬 Deep Research Agent v2 (Production)")
    print("=" * 60)
    print(f"Topic: {topic}")
    print("=" * 60 + "\n")

    graph = build_research_graph()

    initial_state = {
        "topic": topic,
        "clarifying_questions": [],
        "user_responses": [],
        "research_brief": "",
        "sub_topics": [],
        "research_findings": {},
        "sources": [],
        "research_gaps": [],
        "draft": "",
        "critique": None,
        "revision_count": 0,
        "final_report": "",
        "status": "starting",
        "current_phase": "scoping",
        "started_at": datetime.now().isoformat(),
        "completed_at": None,
        "total_tokens_used": 0,
        "estimated_cost_usd": 0.0,
        "errors": [],
        "trace_id": None,
        "span_ids": []
    }

    config = {
        "configurable": {
            "thread_id": thread_id or f"research-{datetime.now().timestamp()}"
        }
    }

    # Stream execution for visibility
    for event in graph.stream(initial_state, config):
        for node_name, output in event.items():
            status = output.get("status", "")
            phase = output.get("current_phase", "")

            if node_name == "clarify" and status == "ready_for_brief":
                print("✅ Topic is clear, generating brief...")
            elif node_name == "generate_brief":
                topics = output.get("sub_topics", [])
                print(f"📋 Brief generated with {len(topics)} sub-topics")
            elif node_name == "supervisor" and status == "research_complete":
                print("✅ Research phase complete")
            elif node_name == "finalize":
                print("📄 Report finalized!")

    # Get final state
    final_state = graph.get_state(config)
    result = final_state.values

    # Save output
    output_dir = Path("output")
    output_dir.mkdir(exist_ok=True)

    safe_topic = "".join(c if c.isalnum() or c in " -_" else "" for c in topic)[:50]
    report_path = output_dir / f"{safe_topic.replace(' ', '_')}.md"
    report_path.write_text(result.get("final_report", ""))

    print("\n" + "=" * 60)
    print("✅ Research Complete!")
    print(f"   Word Count: {len(result.get('final_report', '').split())}")
    print(f"   Sources: {len(set(result.get('sources', [])))}")
    print(f"   Revisions: {result.get('revision_count', 0)}")
    print(f"   Output: {report_path}")
    print("=" * 60)

    return result

if __name__ == "__main__":
    import sys

    topic = sys.argv[1] if len(sys.argv) > 1 else "The Impact of AI Agents on Software Engineering in 2025"

    result = run_research(topic)
```

```python
# agents/scoping.py (enhanced with approval gate)
from langgraph.types import interrupt

def brief_generation_node_with_approval(state: ResearchState) -> dict:
    """Generate brief and pause for human approval.

    This implements human-in-the-loop for the critical scoping decision.
    The agent pauses after generating the brief, allowing the user to:
    1. Review proposed sub-topics
    2. Modify the research scope
    3. Add specific questions
    4. Cancel if the direction is wrong
    """
    agent = ScopingAgent()

    clarifications = "\n".join(state.get("user_responses", []))
    brief = agent.generate_brief(state["topic"], clarifications)

    # Pause for human approval
    approval = interrupt({
        "type": "brief_approval",
        "message": "Please review the research brief before proceeding.",
        "brief": brief.model_dump(),
        "estimated_time": "5-10 minutes",
        "estimated_cost": "$0.50-$2.00",
        "options": ["approve", "modify", "cancel"]
    })

    if approval.get("action") == "cancel":
        return {"status": "cancelled", "current_phase": "cancelled"}

    if approval.get("action") == "modify":
        # User provided modifications
        modified_topics = approval.get("sub_topics", brief.sub_topics)
        modified_questions = approval.get("key_questions", brief.key_questions)

        brief.sub_topics = modified_topics
        brief.key_questions = modified_questions

    return {
        "research_brief": brief.model_dump_json(),
        "sub_topics": brief.sub_topics,
        "status": "brief_complete",
        "current_phase": "research"
    }
```

### 2. Prompt Caching (Up to 90% Cost Reduction)

{/* IMAGE_PLACEHOLDER: A before/after comparison showing prompt caching impact. Left side: Traditional approach with full prompt processing on each call (show repeated system prompts being processed). Right side: Cached approach with only dynamic content being processed (show cached prefix in green, new content in blue). Include cost savings calculation: "$2.00 → $0.20 (90% savings)". Prompt caching is one of the most impactful cost optimizations available in 2025. By structuring prompts so providers can reuse processed prefixes, you can dramatically reduce costs.

```python
# utils/prompt_cache.py
"""
Prompt Caching Strategy:
- OpenAI: Automatic caching for prompts > 1024 tokens (50% discount)
- Anthropic: Explicit cache_control blocks (90% discount on cached, 25% write premium)
- Google: Context caching API for repeated context

Key insight: Structure prompts with STATIC content first, DYNAMIC content last.
"""

# Example: Optimized prompt structure for caching
RESEARCH_SYSTEM_PROMPT = """You are a focused research analyst...
[500+ tokens of detailed instructions that NEVER change]
[Examples and formatting guidelines]
[Citation requirements]
"""  # This prefix gets cached

def create_cacheable_research_prompt(sub_topic: str, search_results: str):
    """Structure prompt for optimal caching."""
    return [
        # STATIC: System prompt (cached after first call)
        {"role": "system", "content": RESEARCH_SYSTEM_PROMPT},

        # DYNAMIC: Changes per request (not cached)
        {"role": "user", "content": f"""
Sub-topic: {sub_topic}

Search Results:
{search_results}

Synthesize these findings into a structured analysis."""}
    ]

# For Anthropic with explicit cache control:
def create_anthropic_cached_prompt(sub_topic: str, search_results: str):
    """Use Anthropic's cache_control for explicit caching."""
    return [
        {
            "role": "user",
            "content": [
                {
                    "type": "text",
                    "text": RESEARCH_SYSTEM_PROMPT,
                    "cache_control": {"type": "ephemeral"}  # Cache this block
                },
                {
                    "type": "text",
                    "text": f"Sub-topic: {sub_topic}\n\nSearch Results:\n{search_results}"
                }
            ]
        }
    ]
```

<Callout type="info">
  **Prompt Caching Impact:** For a research agent making 20 LLM calls with
  similar system prompts, prompt caching can reduce costs from ~$2.00 to
  ~$0.40—an 80% reduction. The key is structuring prompts with static content
  first.
</Callout>

### 3. Token Usage Tracking

```python
# utils/cost_tracker.py
from dataclasses import dataclass, field
from typing import Dict
import os

# 2025 pricing per 1M tokens
COSTS = {
    "gpt-4o": {"input": 2.50, "output": 10.00},
    "gpt-4o-mini": {"input": 0.15, "output": 0.60},
    "claude-3-5-sonnet-20241022": {"input": 3.00, "output": 15.00},
    "claude-3-5-haiku-20241022": {"input": 0.25, "output": 1.25},
    "gemini-2.0-flash": {"input": 0.075, "output": 0.30},
}

# Cached token discounts
CACHE_DISCOUNTS = {
    "openai": 0.50,      # 50% off for cached tokens
    "anthropic": 0.90,   # 90% off for cached tokens (but 25% write premium)
    "google": 0.75,      # 75% off for cached context
}

@dataclass
class CostTracker:
    """Track token usage and estimated costs."""
    usage: Dict[str, int] = field(default_factory=lambda: {"input": 0, "output": 0})
    cached_tokens: int = 0
    model_usage: Dict[str, Dict[str, int]] = field(default_factory=dict)
    budget_limit: float = field(default_factory=lambda: float(os.getenv("MAX_RESEARCH_COST_USD", "2.00")))

    def add_usage(self, model: str, input_tokens: int, output_tokens: int, cached_input: int = 0):
        self.usage["input"] += input_tokens
        self.usage["output"] += output_tokens
        self.cached_tokens += cached_input

        if model not in self.model_usage:
            self.model_usage[model] = {"input": 0, "output": 0, "cached": 0}
        self.model_usage[model]["input"] += input_tokens
        self.model_usage[model]["output"] += output_tokens
        self.model_usage[model]["cached"] += cached_input

    def estimate_cost(self) -> float:
        """Estimate total cost in USD."""
        total = 0.0
        for model, usage in self.model_usage.items():
            costs = COSTS.get(model, COSTS["gpt-4o-mini"])

            # Regular tokens
            regular_input = usage["input"] - usage.get("cached", 0)
            total += (regular_input / 1_000_000) * costs["input"]
            total += (usage["output"] / 1_000_000) * costs["output"]

            # Cached tokens (discounted)
            if usage.get("cached", 0) > 0:
                provider = "anthropic" if "claude" in model else "openai"
                discount = CACHE_DISCOUNTS.get(provider, 0.5)
                total += (usage["cached"] / 1_000_000) * costs["input"] * (1 - discount)

        return total

    def check_budget(self) -> tuple[bool, float]:
        """Check if we're within budget. Returns (within_budget, remaining)."""
        current = self.estimate_cost()
        remaining = self.budget_limit - current
        return remaining > 0, remaining

    def summary(self) -> str:
        within_budget, remaining = self.check_budget()
        status = "✅" if within_budget else "⚠️ OVER BUDGET"

        return f"""
Token Usage Summary:
  Total Input: {self.usage['input']:,} tokens
  Total Output: {self.usage['output']:,} tokens
  Cached Tokens: {self.cached_tokens:,} (saved ~${self.cached_tokens / 1_000_000 * 2:.4f})
  Estimated Cost: ${self.estimate_cost():.4f}
  Budget Remaining: ${remaining:.4f} {status}
        """
```

### 4. Research Result Caching

```python
# utils/cache.py
import hashlib
import json
from pathlib import Path
from typing import Optional
from datetime import datetime, timedelta

class ResearchCache:
    """Cache research results to avoid redundant API calls."""

    def __init__(self, cache_dir: str = ".cache", ttl_days: int = 7):
        self.cache_dir = Path(cache_dir)
        self.cache_dir.mkdir(exist_ok=True)
        self.ttl = timedelta(days=ttl_days)

    def _hash_query(self, query: str) -> str:
        return hashlib.md5(query.lower().strip().encode()).hexdigest()[:16]

    def _is_expired(self, cache_file: Path) -> bool:
        if not cache_file.exists():
            return True
        mtime = datetime.fromtimestamp(cache_file.stat().st_mtime)
        return datetime.now() - mtime > self.ttl

    def get(self, query: str) -> Optional[dict]:
        """Retrieve cached results if fresh."""
        cache_file = self.cache_dir / f"{self._hash_query(query)}.json"

        if self._is_expired(cache_file):
            return None

        try:
            data = json.loads(cache_file.read_text())
            print(f"📦 Cache hit for: {query[:50]}...")
            return data
        except (json.JSONDecodeError, IOError):
            return None

    def set(self, query: str, results: dict):
        """Cache results with metadata."""
        cache_file = self.cache_dir / f"{self._hash_query(query)}.json"

        data = {
            "query": query,
            "results": results,
            "cached_at": datetime.now().isoformat()
        }
        cache_file.write_text(json.dumps(data, indent=2))

    def clear_expired(self):
        """Remove expired cache entries."""
        for cache_file in self.cache_dir.glob("*.json"):
            if self._is_expired(cache_file):
                cache_file.unlink()
```

```python
        session_id=session_id,
        user_id=user_id,
        tags=["deep-research", "production"]
    )

def trace_node(node_name: str):
    """Decorator to trace individual graph nodes."""
    def decorator(func):
        @wraps(func)
        def wrapper(state, *args, **kwargs):
            trace = langfuse.trace(
                name=f"node:{node_name}",
                metadata={
                    "phase": state.get("current_phase"),
                    "status": state.get("status")
                }
            )

            try:
                result = func(state, *args, **kwargs)
                trace.update(
                    output=result,
                    level="DEFAULT"
                )
                return result
            except Exception as e:
                trace.update(
                    output={"error": str(e)},
                    level="ERROR"
                )
                raise
            finally:
                langfuse.flush()

        return wrapper
    return decorator
```

```python
# utils/evaluation.py
from pydantic import BaseModel, Field
from typing import List
from langchain_openai import ChatOpenAI

class ResearchEvaluation(BaseModel):
    """Structured evaluation of research output."""

    # Factual Quality
    factual_accuracy: int = Field(ge=1, le=10, description="Are claims accurate and verifiable?")
    source_quality: int = Field(ge=1, le=10, description="Are sources authoritative and relevant?")
    citation_coverage: int = Field(ge=1, le=10, description="Are claims properly cited?")

    # Completeness
    topic_coverage: int = Field(ge=1, le=10, description="Does it cover all aspects of the topic?")
    depth: int = Field(ge=1, le=10, description="Is the analysis sufficiently deep?")

    # Coherence
    organization: int = Field(ge=1, le=10, description="Is it well-structured and logical?")
    clarity: int = Field(ge=1, le=10, description="Is it clear and readable?")

    # Usefulness
    actionability: int = Field(ge=1, le=10, description="Does it provide actionable insights?")
    audience_fit: int = Field(ge=1, le=10, description="Is it appropriate for the target audience?")

    # Issues
    factual_errors: List[str] = Field(default_factory=list)
    missing_topics: List[str] = Field(default_factory=list)
    suggestions: List[str] = Field(default_factory=list)

    @property
    def overall_score(self) -> float:
        """Weighted average of all dimensions."""
        weights = {
            "factual_accuracy": 0.20,
            "source_quality": 0.15,
            "citation_coverage": 0.10,
            "topic_coverage": 0.15,
            "depth": 0.10,
            "organization": 0.10,
            "clarity": 0.10,
            "actionability": 0.05,
            "audience_fit": 0.05
        }

        total = sum(
            getattr(self, dim) * weight
            for dim, weight in weights.items()
        )
        return round(total, 2)

{reference_sources or 'Not provided'}

Identify specific factual errors, missing topics, and suggestions for improvement."""

        return self.structured_llm.invoke(prompt)
```

## Deployment Checklist

{/* IMAGE_PLACEHOLDER: A deployment pipeline visualization showing stages: Pre-Deployment (environment setup, dependencies) → Smoke Tests (4 test scenarios with pass/fail indicators) → Production Deployment → Post-Deployment Monitoring (metrics dashboard) → Rollback Plan (emergency procedures). Use a horizontal pipeline with checkpoints and status indicators. Style: DevOps pipeline diagram with green/red status lights. */}

Before deploying your research agent to production:

### Pre-Deployment

- [ ] Environment variables configured:
  - [ ] `OPENAI_API_KEY` - Valid OpenAI API key with GPT-4 access
  - [ ] `TAVILY_API_KEY` - Valid Tavily API key
  - [ ] `MAX_RESEARCH_COST_USD` - Budget limit (default: 2.00)
  - [ ] `MAX_REVISIONS` - Critique loop limit (default: 3)
  - [ ] `LANGFUSE_*` - Observability credentials (optional but recommended)
- [ ] Dependencies installed: `langgraph`, `langchain`, `langchain-openai`, `tavily-python`, `pydantic`, `langfuse`
- [ ] Output directory exists and is writable: `./output/`
- [ ] Cache directory exists: `./.cache/`

### Smoke Tests

- [ ] **Test 1: Clear Topic** - Submit "Impact of transformer architecture on NLP" → Report generated in < 5 min
- [ ] **Test 2: Vague Topic** - Submit "AI" → Clarifying questions returned
- [ ] **Test 3: Cost Limit** - Set limit to $0.10, submit complex topic → Budget exceeded notification
- [ ] **Test 4: Resume** - Start research, kill process, restart → Research resumes from checkpoint

### Post-Deployment Verification

- [ ] Monitor first 10 production runs for:
  - [ ] Completion rate > 95%
  - [ ] Average cost within budget
  - [ ] No API errors in logs
- [ ] Verify traces are being recorded in observability platform
- [ ] Confirm cache is reducing redundant API calls

### Rollback Plan

1. Revert to previous container image
2. Clear any corrupted checkpoint data: `rm -rf ./.checkpoints/*`
3. Notify users of temporary unavailability
4. Investigate logs and traces for root cause
